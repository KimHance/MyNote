# 아직 안 정한 것

옛 기능 문서의 열린 질문과 옛 결정 기록의 열림 항목을 2026-11-24 문서 체계를 옮기며 그대로 모았다.
그 뒤 닫혔는지는 확인하지 않았다 — 닫은 줄은 지운다. 문서 체계 밖 문서다(`docsys check` 가 읽지 않는다).
번호는 옛 문서의 질문 번호 · 결정 기록 번호다.

## 첫 앱 (기획 001)

- 9.2 #6 — Medium 이상에서 ☰ 가 고정 패널을 접고 펴는 현재 동작을 유지할지, 설계 문서대로 Compact 에서만 보일지. 뒤로가기의 "패널 접기" 단계가 이 토글에 기대고 있다.
- 9.2 #11 — 액세스 토큰을 앱 전용 폴더에 평문으로 저장하는 것을 언제 암호화할지(저장소 클래스만 바꾸면 되도록 좁혀 둠).
- 9.2 #12 — 프로세스가 죽으면 백스택 · 열린 드로어 · 퀴즈 진행이 사라지고 홈으로 돌아오는 것을 그대로 받아들일지.
- 9.2 #3 / 8.2 #3 — 토큰 편집 중 키보드가 떠 있으면 뒤로가기가 키보드 → 편집기 → 화면 순으로 세 번 드는 것을 받아들일지(설계는 한 번에 편집 닫힘).

## 퀴즈 (002)

- 9.2 #5 — 설계 문서에는 생성 중 그만두기에 "되돌리기" 스낵바가 있지만 생성 취소는 결과가 사라지므로 성립하지 않는다. 그 문구를 폐기할지 정해야 한다.
- 9.1 — 퀴즈 중 Medium 이상의 목록 패널에서 다른 노트를 고르면 퀴즈는 그대로 진행되고 오버레이의 노트 제목만 바뀌는지(추정, 기기 미확인).
- 9.1 — 저장 공간이 모자라 받는 중 멈춘 경우가 "연결 끊김" 으로 보이는 것은 모델 받기(003) 쪽 질문이다.

- 열린 질문 9: 기기에서 못 본 것 — 실패 알림 `다시 시도`, 다 받음 → 파일 확인 → `받았습니다`, 재시도 → 다시 받기, 서버 오류로 예약된 재시도, 알림을 끈 채 받기, 실기기. 다음에 모델을 실제로 받을 때 본다.
- 열린 질문 10: 작업 관리자에서 사용자가 작업을 멈춘 경우도 재시도 알림이 남는다(앱의 취소만 사용자 취소로 본다).
- 열린 질문 11: 코드 이름이 하는 일과 어긋난다 — `HubHeaders.kt`(Range 계열만 남음), `ModelWaitNotice`(이제 쉬는 동안 알림 조정 전체). 다음 정리 때.

## 북마크 (004)

- 9.2 #14: 동기화로 원격에서 지워진 노트의 북마크를 지우는 현재 방식(결정 D5)이 맞는지. 같은 파일 이름으로 노트가 돌아오면 북마크도 되살아나길 원하는 작성 습관이 있는지 확인이 남아 있다.
- 9.2 #15: Compact 에서 북마크 탭 전환이 기존 push 슬라이드(340ms)인 것을 받아들일지, 북마크 엔트리에만 페이드를 따로 줄지.
- 9.2 #18: 리더 토글을 끌 때 되돌리기가 없다. 실수로 껐다 다시 켜면 북마크 시각이 새로 찍혀 순서가 바뀌는데, 끔 스낵바에도 되돌리기를 붙일지.
- 9.2 #19: 북마크 백업. DataStore 파일이라 앱 데이터 삭제 · 기기 교체에서 사라지고, 저장소에 쓰는 것은 읽기 전용 원칙과 충돌해 하지 않았다. 별도 결정이 필요한지.
- 9.2 #20: 되돌리기 유효 기간을 스낵바 동안(현재)으로 둘지, 퀴즈 되돌리기처럼 3.2초 타이머를 둘지.
- 9.2 #23: 패널을 접고 펴면 북마크 화면이 한 단과 2단 사이를 오간다. 받아들일지, 창 폭만으로 고정할지.
- 9.2 #24: 가로 폰에서 시안은 드로어 + 2단이지만 코드는 고정 패널 + 한 단이다. 어느 쪽을 정본으로 할지.
- 9.2 #25: 코드 블록 · 목록만 있는 노트는 큰 카드가 제목뿐이다. 첫 코드 줄을 발췌로 보일지(지금은 발췌 줄 없음).
- 9.2 #26: 큰 카드를 해제한 직후 같은 자리의 버튼을 다시 누르면 승격된 노트까지 빠진다. 승격 동안 버튼을 비활성화할지.
- 9.2 #28: 북마크가 하나뿐일 때 아래가 빈 공간이다. 안내 문구를 둘지.

## 통계 (005)

- 9.2 #29: 노트 폴더가 하나 늘어 카테고리가 6개를 넘으면 6번째부터 윤곽으로 그린다. 디자이너가 팔레트를 늘릴지.
- 9.2 #31: 읽은 시간은 리더가 맨 위이고 앱이 보이면 센다(드로어가 덮어도, 분할 화면에서 다른 앱에 포커스가 있어도). 더 엄격하게 셀지.
- 9.2 #32: 기록을 시작하기 전에 만든 북마크의 보조 줄 "기록 시작 뒤 연 적 없음" 문구가 어색하면 그 북마크를 "오래 안 본" 목록에서 뺄지.
- 9.2 #34: 요약 문장 길이(지시 40/80자, 파서 상한 48/100자)가 카드 높이와 맞는지 디자이너 확인.
- 9.2 #35: 기록 꺼짐 안내 한 줄의 위치(카드 위)와 문구 확인. 핸드오프에 없던 것이다.
- 9.2 #37: 0단계(기록)와 1단계(화면)를 같은 릴리즈로 묶을지. 구현은 같은 라운드에 끝났다.
- 9.2 #39: 충전 중 하루 한 번 워커가 프로세스를 띄워 판정만 하고 끝난다. 확인 주기를 2–3일로 늘릴지.
- 9.2 #40: 통계의 번호 행(`NumberedRow`)과 북마크의 `BookmarkRow`가 두 벌이다. 북마크 행을 공용 행 + 해제 버튼으로 통합할지.
- 9.2 #46: 충전 판정은 "꽂힘"이 아니라 "잔량이 오르는 중"이다. 저전류 충전만 쓰는 사용자는 워커가 거의 안 돌 수 있다. 실사용 로그로 확인할지.
- 9.2 #48: 오답이 여러 주제에 걸쳐 8개 섞이면 모델이 문장 없이 태그만 낸다(greedy라 재시도도 같다). 입력을 가장 많이 틀린 노트로 좁힐지, 자리째 없음으로 둘지.
- 9.2 #49: 비교할 지난주가 없는데도 요약 detail에 "지난주와 비슷합니다"가 나온 적이 있다. 비교가 없을 때 "지난주와 비교하지 말 것" 규칙을 넣을지.
- 9.1 #33–#38 (기기로 못 본 것): 통계 화면 TalkBack 실제 낭독, 모션, 실제 충전기에서 워커가 스스로 시작하는 것, 실제 Parse/Engine/Timeout 실패 화면.
