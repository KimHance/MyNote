# Markdown note format and the format engine

Source: rebuilt from the old feature document `docs/spec/note-format.md` as of commit c8c54350 (work of 2026-10-07 on the Markdown engine; later changes up to 2026-10-14 that the document records).

## Plan
- why: Note bodies were block JSON, hard for a person to write and unreadable on GitHub, with no tables, italics or nested lists. Notes are now written as Markdown and the app turns them into the same blocks it always drew, while JSON notes in installed apps, templates and old repositories keep reading.
- flow: The author writes `notes/<group>/<id>.md` (front matter with title and date, then GFM body) and commits; the hook rebuilds `notes/index.json` in the same commit. After a sync the app picks the format from the list entry's path extension, checks limits, converts with the JetBrains Markdown engine and shows blocks; a newer app re-converts cached originals without the network.
- not doing: No folder-scan repositories without an index; no link opening or image drawing (text only); no HTML, math, diagram or code colouring; no footnotes; no lists or code inside quotes drawn as blocks; no partial display of over-limit notes and no parse time limit; the index generator does not check Markdown bodies; no body selection or copy in the reader; no conversion script kept in the repository; no write path from the app to repository notes; the public template kit follows separately (see 008-note-template).

## Items
| ID | What | Accept |
|---|---|---|
| NF-1 | A Markdown note is `notes/<group>/<id>.md`: id is the file name, group the folder, title and date come from front matter (first line `---`, `key: value` lines, closing `---`; only `title` and `date` in `YYYY.MM.DD`); CRLF and a leading BOM are normalised; the app reads only the boundary, front matter never becomes a block, and an unclosed boundary makes the whole file the body | The generator lists a valid note and fails with path and reason on each front-matter error kind; the app drops front matter, also CRLF; the shared boundary fixture folder gives the same verdict in generator and app (`NoteFormatTest` NF-1 cases, `notes-tests/test_gen_index.py`) |
| NF-2 | One entry point picks the format from the path (`.md` any case is Markdown, anything else or no path is JSON); every place that turns an original into blocks uses it; it never throws: exceptions become a whole-note box and out-of-memory becomes that note's over-limit box | `NoteFormatTest` NF-2 cases; `NoteFormatSyncTest`: a note that makes the parser fail or run out of memory leaves sync successful and other notes applied |
| NF-3 | Block syntax maps to today's blocks: headings 1 to 6, paragraphs, fenced and indented code, one quote block per quote (non-paragraph content joined as text lines), bullet and numbered lists, dividers; blank lines are no block; Markdown has no spacer | `MarkdownConverterTest` table of inputs and expected blocks; instrumented `NoteContentSemanticsTest`: heading blocks read as headings |
| NF-4 | Text shapes: bold, code (verbatim), italic and strike-through as new shapes, overlapping freely; code spans take only strike-through; inside quotes italic and code stand upright; soft break is a space, hard break a line break; the reader announces strike-through once per run | `MarkdownConverterTest` shapes table; `NoteSpansTest`; instrumented `NoteContentSemanticsTest` |
| NF-5 | GFM tables are a new block with a header row, body rows and per-column alignment; short rows are padded, extra cells dropped, escaped pipes stay text even in code, a leading quote mark in a cell is text; at most 4,096 cells per note; column widths follow three steps and scroll sideways when the minimum overflows; the reader announces rows, columns and header cells | `MarkdownConverterTest` table cases; `TableColumnWidthsTest`; `NoteBlockMapperTest`; instrumented `NoteContentSemanticsTest` |
| NF-6 | List items hold sub-blocks (sub-lists, paragraphs, code, quotes, tables) keeping the list kind; checkbox items show on and off and are announced (also in numbered lists); numbered lists keep the start number; block depth is at most 32 and the drawn indent stops at 3 levels | `MarkdownConverterTest` NF-6 cases; `NoteListMarkerTest`; `NoteBlockMapperTest` |
| NF-7 | Syntax the app does not draw shows as text, never as a box: links and references as their text, unresolved brackets verbatim, images as alt text, autolinks as the address, inline HTML verbatim, HTML blocks as a code block, math and highlight as source text, alerts as quotes, footnote lines and references verbatim, escapes and entities decoded | `MarkdownConverterTest` text-only table with zero boxes |
| NF-8 | Limits are one set of values used for screening, conversion and box wording: original over 512KB, container nesting over 32 levels or a line prefix over 64 shares is screened before the engine runs; block depth over 32, table cells over 4,096 and a block cache over 1MB give a whole-note over-limit box; a box row keeps no original in the cache and reads it from the original column; the list never reads originals; the reader hides the quiz card for such notes; no time limit | `MarkdownLimitsTest`, `ResultLimitsTest`, `BlockCacheTest`, `NoteFormatSyncTest`, `NoteRowBudgetTest` (cursor window), `NoteBlockMapperTest` (numbers come from the limit values) |
| NF-9 | A parse-rule change raises the parse version; after an app upgrade stale cache rows are re-converted from the stored original and path without the network, touching derived columns only, failures becoming boxes, and not counted as updates | `NoteFormatSyncTest`, `EngineVersionTest`, instrumented `NoteDaoTest` |
| NF-10 | First sentence and quiz plain text follow one rule for Markdown notes: first paragraph, else list items in document order; strike-through kept as `~~text~~` only in quiz text; tables are no first-sentence candidate; items and sub-blocks indent two spaces per depth; checkbox items as `- [x] ` or `- [ ] ` in quiz text only (the first sentence takes the item's text alone) | `NoteExcerptTest`, `GenerateQuizUseCaseTest` |
| NF-11 | The 22 migrated notes give the same blocks, first sentences and quiz text as their JSON originals (spacer excepted), checked against fixed copies; every note under `notes/` reads with no box | `ParityTest` |
| NF-12 | JSON originals are read only as the closed format-1 set; unknown types and fields read as before, and the cache bytes of today's blocks do not change | `CacheCompatTest`, `MyNoteJsonFormatTest`, `NoteDtoSerializationTest`, `ReparseEquivalenceTest` |
| NF-13 | `notes/gen_index.py` reads `.md` and `.json` together, makes Markdown entries from front matter without checking bodies, fails on duplicate ids and on an extension that differs only by case, uses the standard library only, and its output equals the committed index | `notes-tests/test_gen_index.py`, `notes-tests/test_repo_index.py` |
