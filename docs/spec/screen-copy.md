| 항목 | 값 |

| 마지막 변경 | 2026-10-11 · 검토 반영 — 끝말 · 쓰지 않는 표현을 시험이 읽는 목록으로 · 인용 문구도 같이 고침 · 넘침 확인 2.0배 상대 비교 |

> 대상은 사용자 눈에 보이거나 낭독되는 문구 전부다 — `:feature:notes` · `:core:design-system` · `:app` · `:core:ai`(알림) 의 `strings.xml`(기준 커밋에서 395개).
> 문구 자체(무엇을 무엇으로 바꾸나 · 용어 표 · 허용 끝말 · 쓰지 않는 표현 · 같이 바뀔 것)는 디자인 문서가 원본이다. 여기엔 지켜야 할 결과만 적는다.

## 기획

### 왜

문구가 여러 작업에서 따로 들어와 같은 것을 다른 말로 부르고(노트를 데려오는 일 하나에 불러오기 · 받기 · 가져오기 · 동기화 · 반영),
번역투 · 피동 · 명사 나열 · 기계가 쓴 듯한 말버릇(추측 · 의인 · 지어낸 진행 단계)이 섞여 있다. 사용자 결정으로 화면 문구 전부를 한 번 다듬는다. 뜻과 동작은 그대로다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 앱을 쓰는 사람 | 화면 · 스낵바 · 대화상자 · 알림을 읽을 때, TalkBack 으로 들을 때 |
| 문구를 더하는 사람 · 에이전트 | 새 문구를 쓸 때 용어 표 · 허용 끝말 · 쓰지 않는 표현을 본다 |

### 흐름

1. 디자이너가 문구 전부를 읽고 용어 표 · 허용 끝말 · 쓰지 않는 표현 · 바꾼 문구 표(전 → 후 · 자리 · 이유) · 같이 바뀔 것 목록을 디자인 문서에 쓴다. 기존 디자인 문서의 문구표도 새 말에 맞춘다.
2. 기능 문서가 인용한 문구가 바뀌면 그 기능 문서도 같이 고친다(기획).
3. 개발이 바꾸기 전 화면을 먼저 찍어 두고, `strings.xml` 값과 거기 묶인 시험 · 템플릿 README · 공개 규격을 같이 고친다. 리소스 이름은 바꾸지 않는다.
4. 시험이 말투 · 쓰지 않는 표현 · 버린 용어를 막는다. 다음에 들어오는 문구도 같은 시험에 걸린다.
5. 끝나면 바뀐 문구 표를 사용자에게 보인다. 적용 전에 따로 승인받지 않는다.

### 안 하는 것

| 안 한다 | 왜 (한 마디) |
|---|---|
| 다국어 · 영어 문구 | 범위 밖(DESIGN 9.1) |
| 화면 모양 · 배치 바꾸기 | 디자인 등급이 문구만이다 |
| 노트 콘텐츠(`notes/`) · 레포 문서 다듬기 | 화면 문구가 아니다 — 인용 글자를 새 값에 맞추는 것만 한다 |
| 리소스 이름 바꾸기 | `feature-modules` FM-11 이 한다 |
| 통계 요약 · 패턴 문장을 만드는 모델 지시문 | 모델만 읽는 글이다 |
| 알림 채널 이름 바꾸기 | 사용자의 알림 설정에 남은 이름이 바뀐다(디자인 문서 동결 목록) |

## 명세

### 동작

| ID | 동작 | 받아들임 기준 | 확인 |
|---|---|---|---|
| SC-1 | 말투는 합니다체 하나다 | 대상 문구의 모든 문장 끝말이 디자인 문서 허용 끝말 목록(서술 `~니다` · 권유 하나로 통일한 `~하세요` 또는 `~해 주세요` · 확인 질문 `~ㄹ까요?` 등)에 있다. 목록에 없는 `요` 끝말(`~나요?` 포함 여부는 목록이 정한다) · 해요체 · 반말 끝말이 0건이다. 예외는 디자인 문서 예외 목록에 이름으로 적은 문구뿐이다(자리만 있는 형식 문구 · 글자 크기 미리보기 문장 · 고유명사) | 파이썬: `SC-1 화면 문구의 끝말은 허용 목록에 있다` |
| SC-2 | 쓰지 않는 표현이 없다 | 디자인 문서의 쓰지 않는 표현 목록(글자 · 정규식 — DESIGN 9.4 의 느낌표 · 이모지 · `클릭` · 내부 용어 · 막연한 오류 문장 · 범위 약속에 이번에 더한 번역투 · 피동 · 말버릇)이 대상 문구에서 0건이다. 범위 약속은 형식 자리 사이의 기간 줄표(`1–%1$d일` · `%1$s – %2$s` 같은 날짜 범위 표기)를 세지 않는다 | 파이썬: `SC-2 화면 문구에 쓰지 않는 표현이 없다` — 목록을 디자인 문서에서 읽는다 |
| SC-3 | 같은 개념엔 같은 말을 쓴다 | 디자인 문서 용어 표의 `버린 말` 열의 말이 대상 문구에서 0건이다. 예외는 용어 표 예외 칸에 이름으로 적은 동결 문구뿐이다(토큰 안내 낱말 · 알림 채널 이름 · 브랜드 제목). 노트를 데려오는 일의 말과 모델을 받는 일의 말이 갈린다. 용어 표가 기존 디자인 문서(`brand` · `model-download` · `note-format` · `repo-connect`)의 용어와 같거나, 다르면 그 문서의 문구표가 새 말로 바뀌어 있다 | 파이썬: `SC-3 용어 표에서 버린 말이 화면 문구에 없다` · 리뷰(디자인 문서 넷과 용어 표 대조) |
| SC-4 | 번역투 · 명사 나열 · 기계가 쓴 듯한 말버릇을 걷는다 | 바꾼 문구 표의 행마다 전 · 후 · 자리 · 이유가 있고, 후 문구가 SC-1 ~ SC-3 을 통과한다. 표에 없는 문구는 값이 기준 커밋과 같다 | 수동(바꾼 문구 표 대조) · 명령: 기준 커밋과 값이 다른 이름 = 표의 이름 |
| SC-5 | 뜻이 그대로다 | 값을 바꾼 문구마다 형식 자리(`%1$d` · `%1$s` · `%2$,d` 등)의 수 · 순서 · 종류가 기준 커밋과 같고, 문자열 배열의 항목 수가 같다. 지운 문구 0 | 명령: 기준 커밋과 형식 자리 비교(차이 0) · `./gradlew lintDebug`(형식 경고 0) |
| SC-6 | 자리마다 문장 모양을 따른다 | 바꾼 문구가 DESIGN 9.4 문장 모양 표를 따른다 — 상태 라벨 · 스낵바 마침표 없음, 안내 문장 마침표 있음, 버튼은 짧은 동사형. 버튼 · 상태 라벨 · 탭 라벨 · 한 줄 고정 자리(디자인 문서에 적은 자리)의 문구는 글자 수가 기준과 같거나 줄었다 | 수동(바꾼 문구 표의 자리 칸) · 명령: 표의 버튼 · 라벨 · 한 줄 행 글자 수 비교 |
| SC-7 | 낭독 문구는 쉼표로 이은 사실이다 | 낭독 문구(내용 설명 · 상태 설명)에 화면 기호(☰ · 화살표 · 가운뎃점 나열)가 0건이고, 보이는 문구와 같은 말을 두 번 읽히지 않는다 | 수동(바꾼 문구 표) · TalkBack 수동(홈 카드 · 북마크 행 · 범주 행 · 퀴즈 선택지) |
| SC-8 | 묶인 곳이 같이 바뀐다 | 디자인 문서 같이 바뀔 것 목록이 모두 새 값과 같다 — ① 템플릿 README 의 앱 용어 일곱과 README 가 인용한 앱 문장(시험이 일부 낱말만 보는 문장 포함) ② DESIGN.md 9.2 표 · 9.4 예 ③ 공개 규격 `notes-kit/SPEC.md` 와 플러그인 사본(바이트 같음) ④ 기능 문서 받아들임 기준 · 결정 · 열린 질문이 인용한 문구 ⑤ 디자인 문서 넷의 문구표. 문구 값을 단언하는 Kotlin · 파이썬 시험이 새 값으로 통과하고 시험 이름은 그대로다 | `python3 -I -m unittest discover public-repos/tests` · `python3 -I -m unittest discover notes-tests` · `./gradlew test` · 명령: 같이 바뀔 것 목록의 인용 글자를 `strings.xml` 값과 대조(차이 0) |
| SC-9 | 바꾼 문구가 화면에서 넘치지 않는다 | 바꾸기 전에 같은 화면을 먼저 찍어 둔다. 바꾼 문구가 있는 화면을 폭 360dp · 시스템 글꼴 1.3배로 열면 버튼 라벨이 한 줄이고 말줄임 · 잘림이 0이다. 2.0배 · 앱 글자 크기 큼에서는 바꾸기 전 캡처보다 말줄임 · 잘림 자리가 늘지 않는다. 가로 800 × 360 첫 실행 연결 화면은 스크롤 없이 두 단 한 화면이다(BR-8). 바꾼 알림 문구는 접힌 알림 한 장으로 본다 | 계측: 기존 `BR-8 가로 800x360 첫 실행 연결 화면은 두 글꼴 모두 스크롤 없이 두 단 한 화면이다` · 수동(에뮬레이터 캡처 — 바꾼 문구가 한 줄 자리에 있는 화면마다 전 · 후 한 쌍 · 알림 한 장) |
