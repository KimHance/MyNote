# 화면 문구 — 어휘 · 문장 · 말투를 사람 말로

| 항목 | 값 |
|---|---|
| 기능 | screen-copy |
| 마지막 변경 | 2026-10-11 · 처음 — 화면 문구 전부를 한 번 다듬는 기준(뜻 그대로 · 합니다체 · 같은 개념엔 같은 말 · 번역투와 명사 나열을 걷음) |
| 디자인 | docs/design/screen-copy.md |
| 항목 ID | SC-번호 (예 SC-3) |

> 대상은 사용자 눈에 보이거나 낭독되는 문구 전부다 — `:feature:notes` · `:core:design-system` · `:app` · `:core:ai`(알림) 의 `strings.xml`.
> 문구 자체(무엇을 무엇으로 바꾸나 · 용어 표 · 쓰지 않는 표현)는 디자인 문서가 원본이다. 여기엔 지켜야 할 결과만 적는다.

## 기획

### 왜

문구가 여러 작업에서 따로 들어와 같은 것을 다른 말로 부르고(받기 · 내려받기 · 다운로드 같은 갈래), 번역투 · 명사 나열 · 기계가 쓴 듯한
말버릇이 섞여 있다. 사용자 결정으로 화면 문구 전부를 한 번 다듬는다. 뜻과 동작은 그대로다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 앱을 쓰는 사람 | 화면 · 스낵바 · 대화상자 · 알림을 읽을 때, TalkBack 으로 들을 때 |
| 문구를 더하는 사람 · 에이전트 | 새 문구를 쓸 때 용어 표 · 쓰지 않는 표현을 본다 |

### 흐름

1. 디자이너가 문구 전부를 읽고 용어 표 · 쓰지 않는 표현 · 바꾼 문구 표(전 → 후 · 자리 · 이유)를 디자인 문서에 쓴다.
2. 개발이 `strings.xml` 값과 거기 묶인 시험 · 템플릿 README 를 같이 고친다. 리소스 이름은 바꾸지 않는다.
3. 시험이 말투 · 쓰지 않는 표현 · 버린 용어를 막는다. 다음에 들어오는 문구도 같은 시험에 걸린다.

### 결정

| # | 날짜 · run | 결정 | 왜 | 누가 | 상태 |
|---|---|---|---|---|---|
| 1 | 2026-10-11 · feature-modules | 문구 다듬기는 모듈 나누기보다 먼저, 리소스 이름을 바꾸지 않고 값만 고친다 | 한 파일에서 끝내고, 이름 바꾸기(`feature-modules` FM-11)와 섞이지 않게 | 메인 | 정함 |
| 2 | 2026-10-11 · feature-modules | 기능 문서 받아들임 기준이 글자 그대로 인용한 문구는 이번에 바꾸지 않는다 | 기존 기능 문서 항목은 전부 그대로다. 꼭 바꿔야 하는 것은 열린 질문으로 | 메인 | 정함 |

### 안 하는 것

| 안 한다 | 왜 (한 마디) |
|---|---|
| 다국어 · 영어 문구 | 범위 밖(DESIGN 9.1) |
| 화면 모양 · 배치 바꾸기 | 디자인 등급이 문구만이다 |
| 노트 콘텐츠(`notes/`) · 레포 문서 다듬기 | 화면 문구가 아니다 |
| 리소스 이름 바꾸기 | `feature-modules` FM-11 이 한다 |
| 통계 요약 · 패턴 문장을 만드는 모델 지시문 | 모델만 읽는 글이다 |

## 명세

### 동작

| ID | 동작 | 받아들임 기준 | 확인 |
|---|---|---|---|
| SC-1 | 말투는 합니다체 하나다 | 대상 `strings.xml` 넷의 모든 문구에 해요체 · 반말 어미(`요` 로 끝나는 서술 · `~어` · `~야` · `~자` 등)가 0건이다 | 파이썬: `SC-1 화면 문구에 해요체와 반말이 없다` |
| SC-2 | 쓰지 않는 표현이 없다 | 디자인 문서의 쓰지 않는 표현(DESIGN 9.4 의 느낌표 · 이모지 · `클릭` · 내부 용어 · 막연한 오류 문장 · 범위 약속, 이번에 더한 번역투 · 말버릇 패턴)이 대상 문구에서 0건이다 | 파이썬: `SC-2 화면 문구에 쓰지 않는 표현이 없다` |
| SC-3 | 같은 개념엔 같은 말을 쓴다 | 디자인 문서 용어 표의 `버린 말` 열의 말이 대상 문구에서 0건이다(고유명사 · 낭독 예외는 표에 적은 것만) | 파이썬: `SC-3 용어 표에서 버린 말이 화면 문구에 없다` |
| SC-4 | 번역투 · 명사 나열 · 기계가 쓴 듯한 말버릇을 걷는다 | 바꾼 문구 표의 행마다 전 · 후 · 자리 · 이유가 있고, 후 문구가 SC-1 ~ SC-3 을 통과한다. 표에 없는 문구는 값이 기준 커밋과 같다 | 수동(바꾼 문구 표 대조) · 명령: 기준 커밋과 값이 다른 이름 = 표의 이름 |
| SC-5 | 뜻이 그대로다 | 값을 바꾼 문구마다 형식 자리(`%1$d` · `%1$s` · `%2$,d` 등)의 수 · 순서 · 종류가 기준 커밋과 같고, plurals 의 수량 갈래가 같다. 지운 문구 0 | 명령: 기준 커밋과 형식 자리 비교(차이 0) · `./gradlew lintDebug`(형식 경고 0) |
| SC-6 | 자리마다 문장 모양을 따른다 | 바꾼 문구가 DESIGN 9.4 문장 모양 표를 따른다 — 상태 라벨 · 스낵바 마침표 없음, 안내 문장 마침표 있음, 버튼은 짧은 동사형. 버튼 · 상태 라벨 · 탭 라벨은 글자 수가 기준과 같거나 줄었다 | 수동(바꾼 문구 표의 자리 칸) · 명령: 표의 버튼 · 라벨 행 글자 수 비교 |
| SC-7 | 낭독 문구는 쉼표로 이은 사실이다 | 낭독 문구(내용 설명 · 상태 설명)에 화면 기호(☰ · 화살표 · 가운뎃점 나열)가 0건이고, 보이는 문구와 같은 말을 두 번 읽히지 않는다 | 수동(바꾼 문구 표) · TalkBack 수동(홈 카드 · 북마크 행 · 범주 행 · 퀴즈 선택지) |
| SC-8 | 시험 · 템플릿 README 에 묶인 문구가 같이 바뀐다 | 템플릿 README 가 앱 용어 일곱과 같은 글자를 쓰고 `public-repos/tests` 가 통과한다. 문구 값을 단언하는 Kotlin · 파이썬 시험이 새 값으로 통과하고 시험 이름은 그대로다. 디자인 문서 문구표가 새 값과 같다 | `python3 -I -m unittest discover public-repos/tests` · `python3 -I -m unittest discover notes-tests` · `./gradlew test` |
| SC-9 | 바꾼 문구가 화면에서 넘치지 않는다 | 바꾼 문구가 있는 화면을 폭 360dp · 시스템 글꼴 1.3배로 열면 버튼 라벨이 한 줄이고 말줄임 · 잘림이 0이다 | 수동(에뮬레이터 캡처 — 바꾼 문구가 있는 화면마다 한 장) |

### 안 바뀔 것

| 무엇 | 확인 |
|---|---|
| 리소스 이름 · 개수 | 명령: 기준 커밋과 이름 집합 비교(문구 단계 안에서 차이 0) |
| 기능 문서 받아들임 기준에 글자 그대로 인용된 문구 | 리뷰 grep(기능 문서의 인용 문구가 `strings.xml` 에 그대로) |
| 앱 이름 · 화면 제목(`MyNote` · 설정 · 북마크 · 통계 · 지난 요약) | `notes-tests/test_brand_title.py`(BR-7) |
| 공용 액션 문구(`ds_action_*`)의 뜻 | 수동(바꾼 문구 표) |
| 노트를 읽지 못한 상자의 문구가 한도 숫자를 형식 자리로 받는다 | 기존 NF 시험 · SC-5 |
