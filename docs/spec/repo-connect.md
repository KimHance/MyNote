## 기획

### 왜

지금 앱이 어느 저장소를 읽을지는 **빌드할 때** 정해진다 — `local.properties` 의 `github.owner/repo/branch` 가 `BuildConfig` 에 박히고, 안 적으면 만든 사람의 저장소가 기본이다. 앱을 받은 사람은 자기 저장소를 연결할 방법이 없고, 공개 빌드에는 만든 사람의 저장소 주소가 들어간다. 토큰도 "공개 저장소만 불러옵니다" 한 줄이 전부라 **비공개 저장소를 연결하는 길**이 설정 한 구석의 토큰 칸뿐이고, 토큰이 틀려도 `연결됨` 으로 보인다.
앱 안에서 저장소 주소(또는 노트 목록 링크)를 받아 연결하고, 공개면 바로, 비공개면 토큰까지 받아 연결해야 한다. 바꾸기·끊기도 앱 안에서 된다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 앱을 처음 깐 사람 | 첫 실행에서 자기(또는 남의 공개) 노트 저장소를 연결할 때 |
| 저장소 주인 | 비공개 저장소를 토큰으로 연결하고, 토큰이 만료되면 바꿀 때 |
| 저장소를 옮기거나 정리하는 사람 | 다른 저장소·브랜치로 바꾸거나 연결을 끊을 때 |
| 이 업데이트 전부터 앱을 쓰던 사람 | 노트가 이미 캐시돼 있는 채로, 처음 저장소를 연결할 때 |

### 흐름

1. 첫 실행(연결 없음 · 노트 0개) → 셸 대신 **연결 화면**. 링크 칸 하나와 `연결`. 플로팅 내비 · 드로어 · 모델 알약은 없다.
2. 링크를 붙이면 앱이 알아본 결과(저장소 · 브랜치 · 목록 위치) 또는 받지 않는 이유가 입력하는 동안 바로 보인다.
3. `연결` → 확인 중. **공개**면 토큰 없이 그대로 확인되고 첫 동기화가 성공하면 연결이 확정된다.
4. 무인증으로 안 보이면(404) 또는 공개 저장소의 무인증 한도에 걸리면 → 같은 화면에서 **토큰 칸**이 펼쳐진다. 토큰을 넣고 `연결` → 확인 → 첫 동기화 → 확정.
5. 확정 뒤 → 홈. 이후 설정 `노트 저장소` 카드에서 **바꾸기**(같은 화면을 위에 쌓는다 · 뒤로 = 설정) · **끊기** · 토큰 바꾸기.
6. 다른 저장소로 바꾸면 확인 → 새 저장소의 첫 동기화가 성공하면 옛 노트가 정리되고 홈으로 간다. 끊으면 확인 → 이 기기의 노트가 지워지고 연결 화면이 된다.
7. 이 업데이트 전부터 쓰던 기기(노트 캐시 있음 · 연결 정보 없음)는 홈이 그대로 보이고 연결 안내가 있다. 처음 연결하는 저장소가 그 노트와 북마크를 이어받는다.

### 안 하는 것

| 안 한다 | 왜 (한 마디) |
|---|---|
| 마크다운 저장소 · Gist · 파일 하나 링크 읽기 | 로드맵 M1·M3 — 읽는 쪽이 없다 |
| GitHub 로그인(OAuth · GitHub App) 으로 레포 고르기 | 로드맵 M2 — 이번엔 토큰 붙여넣기만 |
| 동시에 저장소 여러 개 연결 | 결정 4 |
| 토큰을 암호화해 저장 · 만료일 표시 | 지금 평문(앱 전용 폴더)이고 로드맵 M1·M2 의 몫 |
| 비공개 저장소의 이미지·첨부 인증 | 지금 노트에 이미지 블록이 없다 |
| 앱에서 노트를 쓰거나 저장소를 만든다 | 읽기 전용 앱 |
| 클립보드를 자동으로 읽어 채운다 · 붙여넣기 버튼 | 사용자가 모르는 새 읽기를 만들지 않는다 |
| 연결 화면에서 처음부터 토큰을 권한다 | 결정 10 — 막혔을 때만 |

| RC-2 | 붙여넣은 링크에서 저장소 · 브랜치 · 목록 위치를 알아본다. 받는 모양: `owner/repo`(`.git` · 끝 `/` 허용) · `github.com/owner/repo` 와 `www.github.com/…`(스킴 없음 허용) · `https://github.com/owner/repo` · `…/tree/<브랜치>` · `…/tree/<브랜치>/<하위 경로>` · `…/blob/<브랜치>/<경로>/index.json` · `https://raw.githubusercontent.com/owner/repo/<브랜치>/<경로>/index.json`. `tree`·`blob` 이 아닌 저장소 하위 페이지(`issues` · `pull/…` · `releases` · `wiki` 등)는 저장소 링크로 읽는다 | 위 모양마다 기대한 (저장소 · 브랜치 · 목록 위치)로 읽힌다. 브랜치가 없으면 "저장소 기본 브랜치", 목록 위치가 없으면 `notes/index.json`, 하위 경로만 있으면 `<하위 경로>/index.json`, `blob`·raw 링크는 그 파일 경로 그대로. 앞뒤 공백 · 줄바꿈 · `?tab=readme` 같은 쿼리 · `#` 조각은 무시하고 호스트는 대소문자를 가리지 않는다. 네트워크를 쓰지 않고, 이유·결과는 입력하는 동안 바로 보인다 | JVM: `RC-2 링크 모양별로 저장소 브랜치 목록 위치를 읽는다`(표 기반, 입력 ≥ 16개) |
| RC-3 | 받지 않는 링크는 이유를 말하고 연결을 시도하지 않는다. 이유는 서로 다른 7종이다: 빈 입력 · `https` 가 아님(`http://`) · GitHub 주소가 아님 · Gist · `*.github.io` · 파일 하나(`index.json` 이 아닌 `blob`·raw 파일) · `owner` 만 있거나 `repo` 가 없음 | 각 입력에서 연결 요청이 0회 나가고 이유 종류가 7개 모두 다르다. `연결` 버튼은 받을 수 있는 링크에서만 켜진다. 이유를 알리는 문구는 디자인 문서 몫 | JVM: `RC-3 받지 않는 링크는 요청 없이 이유 7종이 다르다`(연결 UseCase 의 요청 수 0 단정 포함) |
| RC-4 | `연결` 을 누르면 **토큰 없이** 저장소와 노트 목록을 확인한다. 이 요청에는 저장된 토큰이 있어도 인증 정보를 싣지 않는다. 공개 저장소면 토큰을 묻지 않고 확인되고, 첫 동기화가 성공하면 연결이 확정된다 | 기기에 다른 저장소의 토큰이 저장돼 있는 상태에서도 무인증 확인 요청의 `Authorization` 헤더가 0회다. 공개 저장소(무인증 200)에서 연결이 확정되고 노트가 채워지며 토큰은 저장되지 않는다 | JVM: `RC-4 무인증 확인에는 저장된 토큰을 싣지 않는다` · `RC-4 공개 저장소는 토큰 없이 연결된다` |
| RC-5 | 무인증 확인이 저장소 404 면 토큰 입력으로 넘어간다. 입력한 링크와 알아본 결과는 그대로 둔다. 비공개일 수도, 주소가 틀렸을 수도 있다는 점을 같이 알린다 | 404 응답에서 연결은 저장되지 않고, 화면이 "토큰 필요" 상태가 되고, 입력한 링크가 지워지지 않는다. 이 상태가 RC-9(목록 없음)와 다른 종류다 | JVM: `RC-5 무인증 404 는 토큰 요청 상태가 된다` |
| RC-6 | 토큰을 넣고 `연결` 하면 **그 후보 토큰으로** 같은 확인을 한다. 확인에 성공하면 토큰을 저장하고 **적용된 것을 확인한 뒤** 첫 동기화를 시작한다. 첫 동기화가 성공해야 연결이 확정되고, 실패하면 토큰은 시도 전 값으로 돌아간다(결정 13) | ① 확인 요청의 헤더는 holder 값이 아니라 후보 토큰(`Bearer <토큰>`)이다. ② 비공개 저장소에서 첫 동기화가 무인증 404 로 실패하지 않는다(토큰이 적용되기 전에 동기화가 먼저 돌지 않는다). ③ 확인 실패 · 첫 동기화 실패 뒤 저장된 토큰이 시도 전과 같다. ④ 연결 + 토큰 저장이 동기화를 두 번 시작하지 않는다(SY-1) | JVM: `RC-6 후보 토큰으로 확인한다` · `RC-6 토큰이 적용된 뒤에 첫 동기화가 돈다` · `RC-6 실패하면 토큰이 시도 전 값이다` |
| RC-7 | 토큰이 필요한 상태의 실패는 원인별로 **다른 종류**로 갈린다: ① 토큰 거부(401) · ② 이 토큰으로는 저장소가 안 보임(저장소 404) · ③ 토큰은 되는데 목록에 접근 못 함(토큰 사용 중 저장소 200 · 목록 404/403 — 콘텐츠 읽기 권한 의심) · ④ 한도 · ⑤ 일시 오류. **한도(④)**는 확인 중이든 첫 동기화 중이든 연결을 저장하지 않고 같은 화면이 토큰 입력(권유) 상태가 된다. 토큰을 넣으면 확인 → 첫 동기화를 다시 한다(결정 10) | 5개 응답 시나리오가 서로 다른 5종 결과다. 무인증 첫 동기화가 한도로 실패하면 연결이 저장되지 않고 화면 상태가 "토큰 권유" 다. 한도 규칙: 429, 또는 403 에 `x-ratelimit-remaining: 0`, 또는 403 에 `retry-after` → 한도. 그 밖의 403 → 접근 불가(②·③ 쪽) | JVM: `RC-7 토큰 실패 5종이 서로 다른 결과다` · `RC-7 한도는 429 또는 403+한도 헤더다` · `RC-7 한도로 첫 동기화가 실패하면 토큰 권유 상태다` |
| RC-8 | 토큰 입력 칸이 보이는 곳(연결 화면 · 설정 토큰 바꾸기)에는 만드는 법 안내가 있다: 종류(세분화된 개인 액세스 토큰) · 범위(이 저장소 하나) · 권한(콘텐츠 읽기 전용) · `토큰 만들기` 버튼(GitHub 토큰 만들기 화면을 외부 브라우저로 연다). 토큰 값이 classic 접두사(`ghp_`)면 권한이 넓다는 경고가 보인다. 토큰 원문은 화면 상태 밖(로그 · 상태 복원)으로 나가지 않는다 | 안내 3가지와 `토큰 만들기` 가 두 곳 모두에 있다. 접두사 판정이 `ghp_` 만 classic 으로 본다. 입력 중 토큰을 담은 객체의 문자열 표현에 토큰 원문이 없다. 브라우저가 없는 기기에서 버튼이 크래시 없이 실패를 알린다 | JVM: `RC-8 classic 접두사면 경고 상태다` · `RC-8 토큰 입력 객체 문자열에 원문이 없다` · 수동: 안내 3가지 · `토큰 만들기` 열림 · 브라우저 없음 |
| RC-9 | **무인증으로** 저장소가 200 인데 목록 파일이 404 면 마크다운 저장소 등 지원하지 않는 형식으로 알린다. 토큰을 쓴 확인에서의 같은 결과는 RC-7 ③ 이다 | 무인증 저장소 200 · 목록 404 에서 연결이 저장되지 않고 결과 종류가 "목록 없음(지원하지 않는 형식)" 이며 RC-5(토큰 필요)·RC-7 ③ 과 다르다 | JVM: `RC-9 무인증 저장소는 열리고 목록이 없으면 지원하지 않는 형식이다` |
| RC-10 | 목록 파일이 JSON 이 아니거나 모양이 달라 읽을 수 없으면 연결하지 않고 알린다. 목록이 **비어 있어도**(`{}`) 연결은 된다 | 깨진 목록 → 연결 저장 안 됨 + 결과 종류 "목록 형식 오류". 빈 목록 → 연결 확정 + 노트 0개(홈 상태는 RC-21) | JVM: `RC-10 읽을 수 없는 목록은 연결하지 않고 빈 목록은 연결한다` |
| RC-11 | 오프라인이면 확인을 시도하지 않고 알린다. 일시 오류(시간 초과 · 5xx)는 다시 시도할 수 있고 입력은 유지된다. 어느 경우도 기존 연결 · 노트 · 토큰은 그대로다 | 네트워크 없음에서 `연결` 이 요청 0회로 "오프라인" 결과를 낸다. 5xx · 시간 초과 → "일시 오류" 결과 + 입력 유지. 둘 다 저장된 연결 · 토큰이 시도 전과 같다 | JVM: `RC-11 오프라인과 일시 오류는 연결을 바꾸지 않는다` |
| RC-12 | 연결이 확정되면 그 정보(저장소 · 브랜치 · 목록 위치 · 공개 여부)가 앱을 다시 켜도 남고, 이후 동기화가 그 연결로 요청한다 | 연결 → 프로세스 재시작 후 같은 저장소 · 브랜치로 `GET contents/<목록 위치>?ref=<브랜치>` 가 나간다. 빌드 설정 값이 달라도 저장된 연결이 이긴다. 저장되는 저장소 이름은 확인 응답의 정식 이름이다 | JVM: `RC-12 저장된 연결이 빌드 시드보다 우선한다` · `RC-12 정식 이름으로 저장한다` |
| RC-13 | 설정 `노트 저장소` 카드가 연결 상태를 보인다: 저장소 이름 · 브랜치 · 공개 또는 토큰 사용 · **마지막 동기화 결과의 종류**. 연결이 없으면 `저장소 연결` 이 보인다. `토큰 확인 필요` 는 마지막 동기화가 토큰 거부(401)이거나, 비공개 연결인데 접근 불가일 때다. 공개 연결의 토큰 없음은 정상이라 경고 배지(드로어 포함)가 뜨지 않는다(결정 18). 마지막 결과는 메모리에만 있고, 앱 시작 직후 첫 동기화가 끝나기 전에는 "결과 없음" 이다 | 상태 매핑 함수가 (마지막 결과 종류 · 공개 여부 · 토큰 유무) → 카드 상태(공개 · 토큰 사용 · 토큰 확인 필요 · 연결 없음 · 결과 없음)와 배지 여부를 낸다: 공개 + 토큰 없음 + 성공 → 배지 없음 · 비공개 + 토큰 없음 → 배지 · 401 → 토큰 확인 필요 · 시작 직후 → 결과 없음. 옛 "무효 토큰도 연결됨" 이 없다 | JVM: `RC-13 카드 상태 매핑` · `RC-13 공개 연결의 토큰 없음은 배지가 없다` · 수동: 카드 4상태 · 드로어 배지 |
| RC-14 | 설정 `바꾸기` 는 연결 화면을 백스택 위에 연다(뒤로 = 설정). 같은 저장소(대소문자 무시)에서 브랜치 · 목록 위치만 바뀐 것이면 아무것도 지우지 않고 바뀐 연결로 다시 동기화한다 | `Foo/Bar` 로 연결된 상태에서 `foo/bar` · 다른 브랜치로 확인하면 같은 저장소로 판정돼 노트 행 · 북마크가 하나도 지워지지 않고, 다음 동기화가 새 브랜치 기준으로 조정한다(목록에 없는 노트만 지움). 뒤로가기가 설정으로 돌아간다 | JVM: `RC-14 같은 저장소는 대소문자 무시로 판정한다` · `RC-14 같은 저장소의 브랜치 변경은 노트를 지우지 않는다` · 수동: 뒤로 = 설정 |
| RC-15 | 다른 저장소로 바꾸면 먼저 확인 대화상자가 지워질 것을 알린다(이 기기의 노트 N개 · 북마크 M개 · 학습 기록은 남음). 이어받기 연결(RC-19)도 새 저장소에 없는 노트가 지워진다는 같은 알림이 있다. 확정은 새 저장소의 확인 + 첫 동기화가 성공한 **뒤에만** 일어나고 그때 옛 노트와 그 북마크가 지워진다 | 취소하면 변화 0. 확정 후 첫 동기화가 실패하면 옛 연결 · 노트 · 북마크 · 토큰이 그대로이고 실패 이유가 보인다. 성공하면 옛 노트와 그 북마크가 지워지고 새 노트가 보인다. 첫 동기화가 도는 동안 목록에 새 저장소 노트가 섞여 보이지 않는다. 새 연결의 식별자가 지금까지 쓴 어떤 연결 식별자와도 다르다(결정 17). 첫 동기화 도중 프로세스가 죽은 뒤 재시작하면 옛 연결 · 옛 노트이고 새 연결의 흔적이 없다 | JVM: `RC-15 새 저장소 동기화가 실패하면 옛 연결이 남는다` · `RC-15 성공하면 옛 소스의 노트와 북마크만 지운다` · `RC-15 동기화 중에는 새 노트가 목록에 안 섞인다` · `RC-15 지운 연결 식별자를 다시 쓰지 않는다` · `RC-15 확정 전 중단은 옛 연결로 돌아간다` · 수동: 확인 대화상자 개수 |
| RC-16 | 연결을 바꾸거나 끊어도 학습 기록(열람 · 퀴즈 · 통계)과 설정(글자 크기 등)은 지워지지 않는다. 지워진 노트의 기록도 통계 화면을 깨지 않는다 | 바꾸기 · 끊기 뒤에도 기록 3종 행 수가 같고 통계 화면이 열린다. 노트를 못 찾는 기록 행은 이름 없이도 안전하게 그려진다(표시 방식은 디자인) | JVM: `RC-16 연결을 바꿔도 학습 기록은 남는다` · 수동: 통계 화면 |

| RC-19 | **시드와 이어받기.** (a) 빌드 시드(`github.owner` · `github.repo` 가 둘 다 있을 때만, 브랜치가 비면 저장소 기본 브랜치)가 있고 연결이 없고 끊은 적이 없으면 첫 실행에서 시드를 연결로 쓴다 — 확인 화면 없이 동기화한다. 이미 노트(옛 연결 정보 없음)가 있으면 그 노트 · 북마크를 이어받는다.
