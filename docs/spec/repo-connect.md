# 노트 저장소 연결

| 항목 | 값 |
|---|---|
| 기능 | repo-connect |
| 마지막 변경 | 2026-10-05 · 처음 — 앱 안에서 링크로 저장소를 연결하고 바꾸고 끊는다 (빌드 설정 의존 제거) |
| 디자인 | docs/design/repo-connect.md |
| 항목 ID | RC-번호 (예 RC-12) |

> 옛 PRD 에서 옮겨 온 것: `features/token.md`(4.5 토큰 관리) 전체 · `screens/settings.md`(3.4)의 **GitHub 섹션**. 설정의 읽기·퀴즈 모델 섹션은 옛 PRD 에 그대로 있다.

## 기획

### 왜

지금 앱이 어느 저장소를 읽을지는 **빌드할 때** 정해진다 — `local.properties` 의 `github.owner/repo/branch` 가 `BuildConfig` 에 박히고, 안 적으면 만든 사람의 저장소(`KimHance/MyNote/main`)가 기본이다. 앱을 받은 사람은 자기 저장소를 연결할 방법이 없고, 공개 빌드에는 만든 사람의 저장소 주소가 들어간다. 토큰도 "공개 저장소만 불러옵니다" 한 줄이 전부라 **비공개 저장소를 연결하는 길**이 설정 한 구석의 토큰 칸뿐이고, 토큰이 틀려도 `연결됨` 으로 보인다.
앱 안에서 저장소 주소(또는 노트 목록 링크)를 받아 연결하고, 공개면 바로, 비공개면 토큰까지 받아 연결해야 한다. 바꾸기·끊기도 앱 안에서 된다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 앱을 처음 깐 사람 | 첫 실행에서 자기(또는 남의 공개) 노트 저장소를 연결할 때 |
| 저장소 주인 | 비공개 저장소를 토큰으로 연결하고, 토큰이 만료되면 바꿀 때 |
| 저장소를 옮기거나 정리하는 사람 | 다른 저장소·브랜치로 바꾸거나 연결을 끊을 때 |

### 흐름

1. 첫 실행(연결 없음 · 노트 0개) → 홈 대신 **연결 화면**. 붙여넣기 칸 하나와 `연결`.
2. 링크를 붙이면 앱이 알아본 결과(저장소 · 브랜치 · 노트 목록 위치)가 바로 보인다. 못 알아보면 이유가 보인다.
3. `연결` → 확인 중. **공개**면 토큰 없이 그대로 연결되고 노트가 받아진다.
4. 무인증으로 안 보이면(404) → 같은 화면에서 **토큰 칸**이 펼쳐진다("비공개 저장소이거나 주소가 틀렸습니다"). 토큰을 넣고 `연결` → 확인 → 연결.
5. 연결 뒤 → 홈. 이후 설정 `노트 저장소` 카드에서 **바꾸기**(같은 연결 화면) · **끊기** · 토큰 바꾸기.
6. 다른 저장소로 바꾸면 확인 → 새 저장소의 첫 동기화가 성공하면 옛 노트가 정리된다. 끊으면 확인 → 이 기기의 노트가 지워진다.

### 안 하는 것

| 안 한다 | 왜 (한 마디) |
|---|---|
| 마크다운 저장소 · Gist · 파일 하나 링크 읽기 | 로드맵 M1·M3 — 읽는 쪽이 없다 |
| GitHub 로그인(OAuth · GitHub App) 으로 레포 고르기 | 로드맵 M2 — 이번엔 토큰 붙여넣기만 |
| 동시에 저장소 여러 개 연결 | 결정 4 |
| 토큰을 암호화해 저장 | 지금 평문(앱 전용 폴더)이고 로드맵 M1·M2 의 Keystore 몫 |
| 비공개 저장소의 이미지·첨부 인증 | 지금 노트에 이미지 블록이 없다 |
| 앱에서 노트를 쓰거나 저장소를 만든다 | 읽기 전용 앱 |
| 클립보드를 자동으로 읽어 채운다 | 사용자가 모르는 새 읽기를 만들지 않는다 |

## 명세

### 동작

| ID | 동작 | 받아들임 기준 | 확인 |
|---|---|---|---|
| RC-1 | 연결 없음 · 노트 0개로 앱을 열면 홈 대신 연결 화면이 보인다 | 새로 설치(빌드 기본 저장소 없음) 첫 실행에서 연결 화면이 뜨고 홈의 "표시할 노트가 없습니다" 는 안 보인다. 노트가 1개 이상 캐시돼 있으면 연결이 없어도 연결 화면 대신 홈이 보인다 | `RC-1 연결이 없고 노트도 없으면 연결 화면이다` · `RC-1 연결이 없어도 캐시된 노트가 있으면 홈이다` |
| RC-2 | 붙여넣은 링크에서 저장소 · 브랜치 · 목록 위치를 알아본다. 받는 모양: `owner/repo` · `https://github.com/owner/repo`(끝 `.git` · `/` 허용) · `…/tree/<브랜치>` · `…/tree/<브랜치>/<하위 경로>` · `…/blob/<브랜치>/<경로>/index.json` · `https://raw.githubusercontent.com/owner/repo/<브랜치>/<경로>/index.json` | 위 7개 입력이 각각 기대한 (저장소 · 브랜치 · 목록 위치)로 읽힌다. 브랜치가 없으면 "저장소 기본 브랜치", 목록 위치가 없으면 `notes/index.json`, 하위 경로만 있으면 `<하위 경로>/index.json`. 앞뒤 공백 · 줄바꿈 · `?tab=readme` 같은 쿼리 · `#` 조각은 무시한다. 네트워크를 쓰지 않는다 | `RC-2 링크 모양별로 저장소 브랜치 목록 위치를 읽는다`(표 기반 단위 시험, 입력 ≥ 12개) |
| RC-3 | 받지 않는 링크는 이유를 말하고 연결을 시도하지 않는다 | 다음 입력에서 요청이 0회 나가고 각각 다른 이유가 보인다: GitHub 가 아닌 주소 · `gist.github.com` · `*.github.io` · 파일 하나(`blob/…/foo.md` 등 `.json` 이 아닌 파일) · `owner` 만 있거나 `repo` 가 없는 주소 · 빈 입력. `http://` 는 받지 않는다(https 만) | `RC-3 받지 않는 링크는 요청 없이 이유가 다르다` |
| RC-4 | `연결` 을 누르면 토큰 없이 저장소와 노트 목록을 확인한다. 공개 저장소면 토큰을 묻지 않고 연결되어 노트가 받아진다 | 공개 저장소(MockWebServer 무인증 200)에서 `Authorization` 헤더가 한 번도 안 나가고, 연결이 저장되고, 첫 동기화가 노트를 채운다 | `RC-4 공개 저장소는 토큰 없이 연결된다` |
| RC-5 | 무인증 확인이 404 면 토큰 입력으로 넘어간다. 입력한 링크와 알아본 결과는 그대로 둔다 | 404 응답에서 연결은 저장되지 않고, 화면이 "토큰 필요" 상태가 되고, 입력한 링크가 지워지지 않는다. 같은 404 라도 "주소가 틀렸을 수도 있다" 는 안내가 같이 있다 | `RC-5 무인증 404 는 토큰 요청 상태가 된다` |
| RC-6 | 토큰을 넣고 `연결` 하면 그 토큰으로 같은 확인을 한다. 성공하면 연결과 토큰이 같이 저장된다. 확인에 실패하면 **토큰도 저장하지 않는다** | 유효 토큰(200)이면 둘 다 저장된다. 401 · 404 · 한도로 실패하면 저장된 토큰이 연결 전과 같다. 토큰을 붙인 요청 헤더가 `Bearer <토큰>` 이다 | `RC-6 확인에 성공해야 토큰이 저장된다` |
| RC-7 | 토큰 실패는 원인별로 다르게 말한다 | 토큰 칸에서: 401 → "토큰이 올바르지 않거나 만료됐습니다" 계열 · 404(토큰 있음) → "이 토큰으로는 이 저장소가 보이지 않습니다" 계열(권한 · 저장소 선택 확인 안내) · 403 한도 → 한도 안내 · 그 외 → 일시 오류. 서로 다른 4개 상태로 구별된다 | `RC-7 토큰 실패 원인이 서로 다른 결과다` |
| RC-8 | 토큰 입력 칸에서 만드는 법을 안내한다: 종류는 세분화된 개인 액세스 토큰(Fine-grained PAT), 저장소는 **이 저장소 하나**, 권한은 **Contents: 읽기 전용**. 기존 방식(classic)의 `repo` 토큰도 되지만 권한이 넓다는 경고를 보인다 | 토큰 칸이 보이는 모든 곳(연결 화면 · 설정 토큰 바꾸기)에서 위 세 가지 안내와 `토큰 만들기` 버튼(GitHub 토큰 만들기 화면을 외부 브라우저로 연다)이 있다. 값이 `ghp_` 로 시작하면 classic 경고가 보인다. 토큰 값은 화면 밖(로그 · 상태 복원)으로 나가지 않는다 | `RC-8 classic 접두사면 경고가 보인다` · 안내 문구 존재는 `수동` |
| RC-9 | 노트 목록 위치에서 목록 파일이 없으면(저장소는 열리는데 `index.json` 이 404) 마크다운 저장소 등으로 보고 안내한다 | 저장소 200 · 목록 404 에서 연결이 저장되지 않고 "이 저장소에는 노트 목록(`index.json`)이 없습니다. 마크다운 저장소는 아직 지원하지 않습니다" 계열이 보인다. 토큰 요청 상태와 구별된다 | `RC-9 저장소는 열리고 목록이 없으면 지원하지 않는 형식이다` |
| RC-10 | 목록 파일이 JSON 이 아니거나 모양이 달라 읽을 수 없으면 연결하지 않고 말한다. 목록이 **비어 있어도**(`{}`) 연결은 된다 | 깨진 목록 → 연결 저장 안 됨 + "노트 목록 형식을 읽을 수 없습니다" 계열. 빈 목록 → 연결 저장됨 + 노트 0개 + "이 저장소에는 아직 노트가 없습니다" 계열 | `RC-10 읽을 수 없는 목록은 연결하지 않고 빈 목록은 연결한다` |
| RC-11 | 오프라인이면 확인을 시도하지 않고 말한다. 일시 오류(시간 초과 · 5xx)는 다시 시도할 수 있다 | 네트워크 없음에서 `연결` 이 요청 없이 "인터넷 연결을 확인하세요" 계열을 보인다. 5xx · 시간 초과는 "잠시 뒤 다시 시도" 계열 + 입력은 유지. 어느 경우도 기존 연결 · 노트는 그대로 | `RC-11 오프라인과 일시 오류는 연결을 바꾸지 않는다` |
| RC-12 | 연결이 저장되면 그 정보(저장소 · 브랜치 · 목록 위치)가 앱을 다시 켜도 남고, 이후 동기화가 그 연결로 요청한다 | 연결 → 프로세스 재시작 후 같은 저장소 · 브랜치로 `GET contents/<목록 위치>?ref=<브랜치>` 가 나간다. 빌드 설정 값이 달라도 저장된 연결이 이긴다 | `RC-12 저장된 연결이 빌드 기본값보다 우선한다` |
| RC-13 | 설정의 `노트 저장소` 카드가 연결 상태를 보인다: 저장소 이름 · 브랜치 · 공개/토큰 사용 여부 · 마지막으로 노트를 받은 결과. 연결이 없으면 `저장소 연결` 이 보인다 | 연결됨 → `owner/repo · 브랜치` 와 `공개` 또는 `토큰 사용`. 연결 없음 → 연결 버튼. 마지막 동기화가 토큰 무효로 실패했으면 `토큰 확인 필요` 상태(옛 PRD 의 "무효 토큰도 연결됨" 이 아니다) | `RC-13 토큰 무효로 실패하면 연결 카드가 확인 필요다` · 나머지 `수동` |
| RC-14 | `바꾸기` 는 연결 화면을 연다. 같은 저장소에서 브랜치 · 목록 위치만 바뀐 것이면 아무것도 지우지 않고 바뀐 연결로 다시 동기화한다 | 같은 `owner/repo` 로 브랜치만 바꿔 확인하면 노트 행 · 북마크가 하나도 지워지지 않고, 다음 동기화가 새 브랜치 기준으로 조정한다(index 에 없는 노트만 지움) | `RC-14 같은 저장소의 브랜치 변경은 노트를 지우지 않는다` |
| RC-15 | 다른 저장소로 바꾸면 먼저 확인 대화상자가 지워질 것을 알려 준다(이 기기의 노트 N개 · 북마크 M개 · 학습 기록은 남음). `바꾸기` 를 확정해도 새 저장소의 확인과 첫 동기화가 성공하기 전에는 옛 노트를 지우지 않는다 | 확정 후 새 저장소 첫 동기화가 실패하면 옛 연결 · 노트 · 북마크가 그대로이고 실패 이유가 보인다. 성공하면 옛 노트와 그 북마크가 지워지고 새 노트가 보인다. 취소하면 아무것도 안 바뀐다 | `RC-15 새 저장소 동기화가 실패하면 옛 연결이 남는다` · `RC-15 성공하면 옛 소스의 노트와 북마크만 지운다` |
| RC-16 | 연결을 바꾸거나 끊어도 학습 기록(열람 · 퀴즈 · 통계)과 설정(글자 크기 등)은 지워지지 않는다 | 바꾸기 · 끊기 뒤에도 기록 3종 행 수가 같고 통계 화면이 열린다. 지워진 노트의 기록이 목록에 그 노트 이름 없이도 깨지지 않고 보인다 | `RC-16 연결을 바꿔도 학습 기록은 남는다` |
| RC-17 | `끊기` 는 확인 대화상자(이 기기의 노트 N개 · 북마크 M개가 지워지고 토큰도 지워집니다) 뒤에 그 연결의 노트 · 북마크 · 토큰을 지우고 연결 없음 상태로 만든다. 다른 소스(없다면 해당 없음)의 노트는 지우지 않는다 | 끊은 뒤: 연결 없음 · 노트 0 · 북마크 중 그 노트 키 0 · 저장 토큰 없음 · 홈 대신 연결 화면(RC-1). 다른 소스 행을 만들어 둔 시험에서 그 행은 남는다. 확인 취소 시 변화 0 | `RC-17 끊으면 그 소스의 노트 북마크 토큰만 지운다` |
| RC-18 | 설정 토큰 줄에서 토큰만 따로 바꾸거나 지울 수 있다(공개 저장소에 한도를 늘리려고 토큰을 추가하는 것 포함). 바꾼 토큰은 RC-6 처럼 확인에 성공해야 저장된다 | 연결된 상태에서 새 토큰 확인 실패 시 기존 토큰이 그대로. `지우기` 는 옛 PRD 4.5 처럼 되돌리기 스낵바. 비공개 저장소에서 토큰을 지우면 다음 동기화가 인증 실패(RC-13 `토큰 확인 필요`)가 된다 | `RC-18 새 토큰 확인에 실패하면 기존 토큰이 남는다` · 지우기 되돌리기는 옛 PRD 4.5 와 같음 `수동` |
| RC-19 | 빌드 설정에 `github.*` 가 있으면 첫 실행(연결 없음 · 저장된 연결 없음)에서 그 값을 연결로 쓴다. 없으면 RC-1. 코드에 박힌 기본 저장소는 없다 | `github.*` 없이 빌드한 앱 설정에 `KimHance` 문자열이 없다(BuildConfig 확인). 있게 빌드하면 첫 실행에 연결 화면 없이 그 저장소가 읽힌다 | `RC-19 빌드 기본값이 없으면 연결 화면이다` · `RC-19 빌드 기본값이 있으면 첫 실행 연결로 쓴다` |
| RC-20 | 이 업데이트 전부터 쓰던 기기는 아무것도 다시 하지 않아도 같은 저장소가 계속 읽힌다 | 옛 빌드(소스 `s0` · 연결 정보 없음 · 노트 22개 캐시)를 덮어 설치한 뒤: 연결 화면이 뜨지 않고, 노트 · 북마크 · 통계가 같고, 다음 동기화가 같은 저장소로 나간다(옛 빌드가 쓰던 값 = 그 시점 빌드 기본값) | `RC-20 옛 DB 를 열면 기존 저장소가 연결로 이어진다` · 기기 확인 `수동` |
