# 기기 노트 — 앱에서 쓰고 가져오는 노트

| 항목 | 값 |
|---|---|
| 기능 | local-notes |
| 마지막 변경 | 2026-10-14 · 고침 1 — 실현성 검토 반영: 주 버튼 하나 · 저장 원문 기준 크기 경계 · 제목 · 그룹 한 줄 상한 · 제목 줄 판정 · 공유 위 공유는 갈아 끼움 · 동작 자리는 디자인 |
| 디자인 | docs/design/local-notes.md |
| 항목 ID | LN-번호 (예 LN-3) |

> 이 문서에서 **기기 노트**는 앱 DB 가 원본인 노트(앱에서 쓰거나 가져온 노트)이고, **저장소 노트**는 연결한 GitHub 저장소에서 불러와 캐시한 노트다.
> 저장소 연결 · 동기화 · 해석 규칙은 각각 `repo-connect` · `sync` · `note-format` 이 맡는다. 이 문서는 그 규칙을 옮기지 않고 항목 ID 로 가리킨다.
> 화면 문구 · 모양 · 자리는 디자인 문서 몫이다. 여기엔 "어떤 상태에서 무엇을 할 수 있고 무엇이 보여야 하나" 만 적는다.

## 기획

### 왜

지금 앱은 저장소를 먼저 만들고 연결해야 노트가 하나라도 보인다. 처음 깐 사람은 GitHub 저장소 · 템플릿 · 토큰부터 알아야 해서 시작이 어렵다.
노선을 바꿔 저장소는 선택으로 두고, 노트가 없는 상태에서 **새 노트 쓰기**와 **가져오기**(다른 앱의 글 공유 · `.md` 파일 · 붙여넣기) 두 길로 시작하게 한다.
이번은 1단계다 — 저장소 붙이기(받아오기 확장)와 저장소로 올리기 · 싱크는 다음 단계다. 지금 연결된 저장소 노트와 북마크 · 퀴즈 · 통계 기록은 그대로 살아야 한다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 앱을 처음 깐 사람(저장소 없음) | 첫 화면에서 바로 노트를 쓰거나 가진 마크다운을 들여올 때 |
| 다른 앱(메모 · 브라우저 · 파일 앱)에 마크다운 글이 있는 사람 | 그 글을 공유하거나 파일로 열어 앱 노트로 만들 때 |
| 이 업데이트 전부터 저장소를 연결해 쓰던 사람 | 올린 뒤에도 저장소 노트 · 북마크 · 기록이 그대로이고, 기기 노트를 더 쓸 때 |

### 흐름

1. 첫 실행(연결 없음 · 노트 0개) → 연결 화면이 아니라 **홈 첫 실행 빈 상태**. 두 길(`새 노트` · `가져오기`)과 그보다 낮은 입구 `저장소 연결` 이 보인다.
2. `새 노트` → 편집기(제목 · 본문 마크다운 글자 그대로) → 미리보기로 리더와 같은 모양을 본다 → `저장` → 그 노트가 리더로 열리고 홈 목록에 보인다.
3. `가져오기` → 파일 열기 또는 붙여넣기를 고른다. 다른 앱에서 글을 공유하면 앱이 열린다. 세 길 모두 **내용을 미리 채운 새 노트 편집기**로 이어지고 저장해야 노트가 된다.
4. 기기 노트는 볼 때 `고치기` · `지우기` 에 닿는다(자리는 디자인). 저장소 노트에는 없다(읽기 전용 그대로).
5. 기기 노트도 검색 · 북마크 · 퀴즈 · 통계에 저장소 노트와 똑같이 들어간다. 목록 · 리더에서 출처(이 기기)가 구별된다.
6. 저장소는 언제든 `저장소 연결`(홈 빈 상태 · 설정 카드)로 붙일 수 있고, 붙이거나 바꾸거나 끊어도 기기 노트는 그대로다.

### 안 하는 것

| 안 한다 | 왜 (한 마디) |
|---|---|
| 저장소 노트를 앱에서 고치거나 지운다 | 결정 2 |
| 기기 노트를 저장소로 올리기 · 싱크 · 저장소 노트를 기기 노트로 바꾸기 | 3단계 |
| 저장소 붙이기(받아오기)의 새 모양(여러 저장소 · 폴더 훑기 등) | 2단계 · `repo-connect` 결정 4 |
| 웹 주소를 받아 본문을 긁어오기 | 결정 3 |
| 서식 단추 · 자동 완성 · 글자 모양 툴바 | 결정 1 |
| 기기 노트를 파일 · 공유로 내보내기 | 범위 밖 — 올리기와 같이 본다(열린 질문 2) |
| 여러 파일 한 번에 가져오기 · 이미지 · 첨부 | 범위 밖 — 노트에 이미지 블록이 없다 |
| 앱이 클립보드를 스스로 읽기 | `repo-connect` 안 하는 것과 같은 원칙 |

### 깨지는 전제

지금 앱과 레포 문서는 "읽기 전용 앱 · 노트는 저장소에서만 온다" 를 전제로 한다. 기기 노트를 들이면 아래 전제가 깨지고, 각 행의 항목이 새 계약을 정한다.

| 지금 전제 | 어디에 기대나 | 이번에 | 항목 |
|---|---|---|---|
| 앱에서 쓰기는 없다(읽기 전용 앱) | 루트 소개 · `repo-connect` 안 하는 것 | 기기 노트만 쓰고 고치고 지운다. 저장소 노트는 그대로 읽기 전용 | LN-3 · LN-9 · LN-11 |
| 노트 행을 쓰는 길은 동기화 하나다 | 데이터 층 안내 문서(동기화 = 유일한 쓰기 경로) | 기기 노트 저장 · 고침 · 지움이 둘째 쓰기 길이다. 동기화는 기기 노트를 건드리지 않는다 | LN-12 |
| 노트 캐시는 언제든 저장소에서 다시 받을 수 있다 | 백업 · 마이그레이션 판단(캐시라 잃어도 된다) | 기기 노트는 DB 에만 있는 원본이다. DB 를 버리는 마이그레이션 · 백업 제외는 데이터를 잃는다 | LN-13 · LN-15 |
| 연결 없음 + 노트 0개 = 연결 화면이 첫 화면 | `repo-connect` RC-1 · 결정 15 | 첫 화면은 홈 첫 실행 빈 상태다 | LN-1 · RC-1 |
| 연결 없음 + 노트 있음 = 옛 캐시이고 첫 연결이 이어받는다 | `repo-connect` RC-1 띠 · RC-19 · 결정 9 | 이어받기 · 연결 안내 띠는 **연결 정보 없는 저장소 노트**에만 해당한다. 기기 노트는 이어받히지 않는다 | LN-12 · RC-1 · RC-19 |
| 끊으면 이 기기의 노트가 다 지워지고 연결 화면이 된다 | `repo-connect` RC-17 · RC-23 | 끊으면 저장소 노트만 지워지고 홈이 된다. 기기 노트는 남는다 | LN-12 · RC-17 · RC-23 |
| 노트의 제목 · 날짜 · 그룹은 저장소 목록(`index.json`)이 준다 | `note-format` NF-1 | 기기 노트는 편집기 · 가져오기 규칙이 준다. 제목 · 그룹 길이를 목록이 거르지 않으므로 앱이 상한을 둔다(목록 질의 한 행 크기) | LN-3 · LN-4 · LN-6 |
| 마크다운 원문 첫 줄 `---` 는 앞머리 경계다 · 크기 한도는 원문 전체에 건다 | `note-format` NF-1 · NF-8 | 기기 노트 본문은 첫 줄이 `---` 여도 본문이고, 저장할 수 있는 크기 경계는 리더의 한도 판정과 같은 원문 기준이다 | LN-3 |
| "이 기기의 노트" = 연결 정보 없는 옛 캐시(저장소 노트) | 연결 안내 띠 · 이어받기 · 바꾸기 · 끊기 확인 대화상자의 문장 | 같은 말이 기기 노트와 겹친다. 저장소 쪽 문장은 "불러온 노트" 뜻으로 부르고 "이 기기" 는 기기 노트에만 쓴다(문구는 디자인) | RC-1 · RC-15 · RC-17 · RC-19 |
| 열린 노트가 사라지는 길은 동기화 삭제뿐이다 | `sync` 안 바뀔 것(열린 노트 삭제 시 닫힘) | 사용자가 지운 기기 노트도 같은 정리를 탄다 | LN-11 |

| LN-3 | **새 노트 편집기.** 칸은 제목 · 그룹(LN-4) · 본문이다. 제목 · 그룹은 **한 줄**이고 각 200자까지다 — 줄바꿈을 붙여 넣으면 공백 하나가 되고 200자를 넘는 글은 칸에 들지 않는다. 본문은 마크다운 글자 그대로 쓰고 서식 단추가 없다(결정 1). **미리보기**는 리더와 같은 해석 결과(`note-format` NF-2 진입점 · 마크다운)를 보인다. `저장` 은 제목과 본문이 둘 다 공백만이 아니고 본문이 **크기 경계** 안일 때만 켜진다. 크기 경계는 리더의 원문 한도(NF-8 의 512KB = 524,288 바이트)를 **저장하는 원문 기준**으로 잰 것이다 — 저장할 수 있는 본문은 리더에서 크기 때문에 상자가 되지 않고, 경계는 524,288 바이트에서 저장 모양이 본문 앞에 붙이는 바이트만큼 작을 수 있다(본문 바이트로 잰다, 글자 수가 아니다). 저장하면 기기 노트 하나가 생긴다. 본문 칸에 쓴 글은 **그대로 본문**이다 — 첫 줄이 `---` 여도 앞머리로 먹히지 않는다 | ① 저장 → 노트 수 +1, 그 노트의 출처 = 기기(LN-5), 리더 블록이 같은 본문을 마크다운으로 해석한 결과와 같다. ② 저장 직전 미리보기 블록 = 저장 뒤 리더 블록. ③ 본문이 `---\ntitle: x\n---\n가` 인 노트를 저장하면 리더 블록에 구분선 · `title: x` 글자가 그대로 있다(앞머리로 사라지지 않는다). ④ 제목 공백 · 본문 공백 → `저장` 꺼짐. 저장할 수 있는 가장 큰 본문(경계 바이트)은 저장되고 리더에 크기 상자가 없다 · 그보다 1 바이트 큰 본문은 `저장` 꺼짐이고 크기 넘음 이유가 보인다 · 524,289 바이트 본문은 늘 꺼짐. ⑤ 깊이 · 표 칸 한도(NF-8 의 다른 한도)를 넘는 본문은 저장되고 리더 · 미리보기가 "한도 넘음" 상자를 보인다(저장소 노트와 같은 규칙). ⑥ 저장 뒤 화면은 그 노트의 리더다(편집기 자리를 리더가 갈아 끼우고 뒤로 = 편집기를 연 화면). ⑦ 제목에 줄바꿈이 든 글을 붙여 넣으면 한 줄이 되고, 201자째부터는 들어가지 않는다(그룹도 같다). 1MB 글을 제목 칸에 붙여 넣어도 홈 목록이 그대로 보인다 | JVM: `LN-3 저장하면 기기 노트가 하나 생기고 리더 블록이 마크다운 결과와 같다` · `LN-3 미리보기와 저장 뒤 리더가 같다` · `LN-3 본문 첫 줄 구분선은 앞머리로 먹히지 않는다` · `LN-3 제목 본문 공백은 저장할 수 없다` · `LN-3 크기 경계는 저장 원문 기준으로 리더 한도와 같다`(경계 · 경계+1 · 524,289) · `LN-3 제목과 그룹은 한 줄 200자다` · `LN-3 다른 한도를 넘는 본문은 상자로 저장된다` · `LN-3 저장 뒤 스택은 편집기 자리에 리더다` · 수동: 미리보기 전환 · 키보드가 본문을 가리지 않는다(실기기 세로 · 가로) · 실기기에서 100KB · 512KB 본문의 입력 지연을 재서 기록한다(받아들임 문턱 아님) |
| LN-4 | **그룹 · 날짜.** 기기 노트의 그룹은 편집기 그룹 칸 값이고 비우면 기본 그룹 하나에 든다. 그룹 이름은 앞뒤 공백을 뺀 글자 그대로 비교하고(대소문자를 가린다) 이름이 같은 그룹은 저장소 노트와 **한 그룹**으로 목록에 보인다. 그룹 칸은 자유 입력이다(있는 그룹에서 고르는 칩 · 자동 완성은 없다). 날짜는 만든 날(기기 시간대, 화면 모양은 저장소 노트와 같은 `YYYY.MM.DD`)이고 고쳐도 바뀌지 않는다 — 가져온 글에 앞머리 날짜가 있으면 그 날이다(LN-6). 목록 순서 규칙은 지금 그대로다(날짜 → 처음 본 시각 → 제목) | 그룹 칸을 비우고 저장 → 기본 그룹에 든다. 그룹 `kotlin` 으로 저장 → 저장소 노트의 `kotlin` 그룹에 섞여 하나의 그룹으로 보인다. 그룹 ` kotlin ` 은 `kotlin` 과 같은 그룹, `Kotlin` 은 다른 그룹이다. 2026-10-14 에 만든 노트를 다음 날 고쳐도 날짜가 `2026.10.14` 다. 같은 날짜의 기기 노트 둘은 나중에 만든 것이 앞이다 | JVM: `LN-4 그룹 칸을 비우면 기본 그룹이다` · `LN-4 같은 이름 그룹은 저장소 노트와 한 그룹이다` · `LN-4 그룹 이름은 공백만 다듬고 대소문자를 가린다` · `LN-4 고쳐도 날짜는 만든 날이다` · 계측: `LN-4 같은 날짜 기기 노트는 나중에 만든 것이 먼저다` |

| LN-6 | **가져오기 — 세 길이 한 규칙.** (a) 다른 앱의 글 공유(LN-8) (b) 파일 열기 — 시스템 파일 고르기로 `.md` · `.markdown`(대소문자 무시) 파일 하나 (c) 붙여넣기 — 사용자가 글 칸에 붙여 넣은 글. 셋 모두 원문(과 이름 후보: 파일 이름 · 공유 제목)을 **같은 가져오기 규칙**에 넣어 **미리 채운 새 노트 편집기**를 연다. 저장하기 전에는 노트가 생기지 않는다. 규칙: 줄 끝 · BOM 은 NF-1 처럼 다듬는다. 원문이 NF-1 경계의 앞머리로 시작하면 `title` · `date` 값을 쓰고 앞머리 전체를 본문에서 뺀다. 제목은 앞머리 `title` → 앞머리 뒤 빈 줄을 건너뛴 첫 줄이 1단 제목 줄(`# ` 로 시작 — 밑줄 제목은 아니다)이면 그 글자(닫는 `#` 은 떼고 인라인 표시는 글자 그대로, 본문에서 그 줄을 뺀다) → 이름 후보(파일 이름은 확장자를 뺀다) → 빈 칸 순이고, LN-3 의 한 줄 200자 규칙으로 다듬는다. 날짜는 앞머리 `date` 가 `YYYY.MM.DD` 모양이면 그 날, 아니면 오늘이다. 나머지는 본문 그대로다 | 규칙 함수 표 시험: 앞머리(title · date) 있음 → 제목 · 날짜가 그 값이고 본문에 `---` · `title:` 줄이 없다. 앞머리 없음 + 첫 줄 `# 제목` → 제목 `제목`, 본문 첫 줄은 그 다음 줄. 첫 줄이 `##` 이거나 밑줄 제목(`제목\n===`)이면 제목으로 쓰지 않는다. `# 가 **나** #` → 제목 `가 **나**`. 빈 줄 둘 뒤의 `# 제목` 도 제목이다. 앞머리 · `#` 없음 + 파일 `flow.md` → 제목 `flow`. 공유 제목만 있음 → 그 글자. 아무것도 없음 → 빈 제목(저장 꺼짐, LN-3 ④). 닫히지 않은 앞머리 → 전체가 본문(NF-1 과 같다). 날짜 `2026-10-14`(모양 틀림) → 오늘.
