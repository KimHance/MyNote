## 기획

### 왜

동기화는 지금 빌드에 박힌 저장소 하나만 읽고, 실패하면 원인과 무관하게 `노트를 불러오지 못했습니다. 연결을 확인하세요.` 한 문장이다. 토큰이 만료돼도, 저장소 주소가 틀려도, 한도에 닿아도 같다. 저장소를 앱 안에서 연결하고 바꾸게 되면(`repo-connect`) 동기화는 ① 연결 정보를 따라 요청하고 ② 연결이 없으면 조용히 쉬고 ③ 원인을 구별해 말하고 ④ 연결을 바꿀 때 지우는 범위를 M0 에서 정한 소스 계약 안에 가둬야 한다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 노트를 읽는 사람 | 앱을 열 때 · 새로고침할 때 · 연결이나 토큰을 바꾼 직후 |
| 저장소 주인 | 새 노트를 push 하고 앱에서 반영을 확인할 때 |

### 흐름

1. 앱 시작 · 새로고침 · 연결 변경 · 적용 토큰 변경 → 동기화.
2. 연결이 없으면 요청 없이 끝난다(실패 아님).
3. 연결이 있으면 그 연결의 목록 → 바뀐 노트만 받기 → 그 연결의 노트만 추가 · 갱신 · 삭제.
4. 실패하면 원인에 맞는 말이 나오고 캐시는 그대로다.

### 결정

M0(`m0-public-safety`)에서 정한 동작 결정을 옮긴다 — 이번 run 이 이 계약 위에서 연결 바꾸기를 만든다.

## 명세

### 동작

| ID | 동작 | 받아들임 기준 | 확인 |
|---|---|---|---|
| SY-1 | 동기화는 앱 시작 1회 · 새로고침 · 적용 토큰 변경 · **연결 변경**에 돈다. 이전 동기화가 돌고 있으면 취소하고 새 것으로 간다(취소는 실패 표시가 아니다) | 연결을 바꾸는 순간 돌던 동기화가 취소되고 새 연결로 한 번 돈다. 취소가 오류 스낵바를 띄우지 않는다 | `SY-1 연결이 바뀌면 돌던 동기화를 취소하고 새로 돈다` |
| SY-2 | 요청은 저장된 연결(저장소 · 브랜치 · 목록 위치)로 만든다. 요청 모양은 지금과 같다 | MockWebServer 에서 연결 `a/b · dev · docs/index.json` 이면 `GET repos/a/b/contents/docs/index.json?ref=dev` 와 노트 경로 `?ref=dev` 가 나간다. 연결을 바꾸면 다음 요청이 새 연결을 쓴다 | `SY-2 요청이 저장된 연결을 따른다` |
| SY-3 | 연결이 없으면 요청을 보내지 않고 성공도 실패도 아닌 "할 일 없음" 으로 끝난다. 캐시된 노트는 그대로 읽힌다 | 연결 없음 + 캐시 노트 3개: 네트워크 요청 0회 · 오류 스낵바 0 · 목록 3개 유지 | `SY-3 연결이 없으면 요청도 오류도 없다` |
| SY-4 | 동기화는 **연결된 소스의 노트만** 추가 · 갱신 · 삭제한다(M0 결정 3) | 소스 A 동기화가 소스 B 의 같은 `docId` 노트를 지우지 않고 갱신하지도 않는다 | `다른 소스의 노트는 지우지 않는다`(`NotesReconcileTest`) · `다른 소스의 같은 docId 는 지우지 않는다`(계측) |
| SY-5 | 실패는 원인별로 구별되어 화면에 전달된다: 인터넷 · 토큰 무효 · 접근 불가 · 한도 · 서버 · 형식. 캐시는 그대로다 | 401 · 404 · 403(한도 헤더) · 429 · 500 · 시간 초과 · 목록 JSON 깨짐 · 오프라인 응답이 각각 서로 다른 실패 종류로 나온다. 어느 경우도 노트 행이 바뀌지 않는다 | `SY-5 실패 응답이 원인 종류로 갈린다` |
| SY-6 | 첫 실행에서 연결 직후 동기화는 `announce=false` 처럼 조용하다(결과 스낵바 없음). 사용자가 누른 새로고침에만 `노트 변경 반영 — …` 이 뜬다 | 연결 직후 동기화는 스낵바 0. 새로고침 + 변경 있음 → 스낵바 | 옛 PRD 4.1 동작 유지 `수동` |

### 안 바뀔 것

| 무엇 | 확인 |
|---|---|
| 형식 오류는 노트 단위로 격리하고 나머지는 반영한다 | `형식 오류 노트는 격리하고 나머지는 반영한다` · `JSON 이 아닌 노트도 목록에 남고 본문은 BrokenNote 다`(`NotesReconcileTest`) |
| 본문 전송이 하나라도 실패하면 아무것도 반영하지 않는다 | `본문 전송이 하나라도 실패하면 아무것도 반영하지 않는다` · `index 를 해석하지 못하면 아무것도 반영하지 않는다` |
| 지우기 보호(소스 목록이 비었고 로컬이 남아 있으면 지우지 않고 실패) | `소스 index 가 비었는데 그 소스 노트가 남아 있으면 지우지 않고 실패한다` |
| 해시가 같으면 본문을 다시 받지 않고, 다르면 받아 갱신한다 · 목록에 없는 노트는 지운다 | `리비전이 같으면 본문을 다시 받지 않는다` · `리비전이 다르면 본문을 다시 받아 갱신한다` · `index 에 없는 로컬 노트는 삭제한다` |
| 원문 채우기 재수신은 갱신으로 세지 않는다 | `원문이 없는 옛 행은 리비전이 같아도 한 번 다시 받고 갱신으로 세지 않는다` |
| 어댑터가 없는 종류의 소스는 동기화도 삭제도 하지 않는다 | `어댑터가 없는 kind 의 소스는 동기화도 삭제도 하지 않는다` |
| 열려 있는 노트가 삭제되면 즉시 닫힌다 · 노트 하나가 열려 있는 동안의 스낵바 동작 | `수동`(옛 PRD 4.1) |
