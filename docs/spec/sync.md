| 항목 | 값 |
|---|---|
| 기능 | sync |
| 마지막 변경 | 2026-10-11 · SY-1 앱에 돌아올 때마다 다시 돌던 동기화를 막음(동작 그대로) |
| 디자인 | docs/design/repo-connect.md |
| 항목 ID | SY-번호 (예 SY-4) |

> 옛 PRD `features/sync.md`(4.1)에서 **이번에 바뀌는 부분과 그 부분이 기대는 계약**만 옮겼다(백필 아님). 해시 비교의 세부 · 스낵바 문구는 옛 PRD 4.1 에 그대로 있다.
> 실패 문구는 이 문서에 쓰지 않는다 — 디자인 문서의 문구표가 원본이다. 여기엔 실패의 **종류**만 적는다.

## 기획

### 왜

동기화는 지금 빌드에 박힌 저장소 하나만 읽고, 실패하면 원인과 무관하게 한 문장이다. 토큰이 만료돼도, 저장소 주소가 틀려도, 한도에 닿아도 같다. 저장소를 앱 안에서 연결하고 바꾸게 되면(`repo-connect`) 동기화는 ① 연결 정보를 따라 요청하고 ② 연결이 없으면 조용히 쉬며 연결을 스스로 만들지 않고 ③ 원인을 구별해 알리고 ④ 연결을 바꿀 때 지우는 범위를 M0 에서 정한 소스 계약 안에 가둬야 한다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 노트를 읽는 사람 | 앱을 열 때 · 새로고침할 때 · 연결이나 토큰을 바꾼 직후 |
| 저장소 주인 | 새 노트를 push 하고 앱에서 반영을 확인할 때 |

### 흐름

1. 앱 시작 · 새로고침 · 연결 변경 · 적용 토큰 변경 → 동기화.
2. 연결이 없으면 요청 없이 끝난다(실패 아님). 동기화가 연결을 새로 만들지 않는다.
3. 연결이 있으면 그 연결의 목록 → 바뀐 노트만 받기 → 그 연결의 노트만 추가 · 갱신 · 삭제.
4. 실패하면 원인 종류가 구별되어 전달되고 캐시는 그대로다.
