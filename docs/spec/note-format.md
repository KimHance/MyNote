> 동기화 순서 · 실패 종류 · 소스 계약은 `docs/spec/sync.md` 가 맡는다. 이 문서는 **본문 파일 한 개를 블록으로 바꾸는 규칙**과 그 규칙을 쓰는 이 레포 도구(목록 생성기 · 훅 · 규격 문서 · 쓰기 스킬)만 쓴다.

> 공개 자산(`public-repos/`)의 형식은 JSON 형식 `1` 그대로다(`note-template`).

## 기획

### 왜

노트 본문이 블록 JSON 이라 사람이 쓰기 어렵고, GitHub 에서 열어도 읽히지 않는다. 표 · 기울임 · 하위 목록처럼 흔한 문법도 없다. 노트를 마크다운으로 쓰면 사람 · 도구 누구나 쓰고 GitHub 에서 그대로 읽힌다. 앱은 마크다운을 GFM 엔진으로 해석해 지금과 같은 블록으로 그린다. 이미 깔린 앱 · 템플릿 · 옛 저장소의 JSON 노트는 계속 읽혀야 한다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 노트를 쓰는 사람(이 레포 주인 · 쓰기 스킬) | 노트를 새로 쓰거나 고쳐 커밋할 때 |
| 노트를 읽는 사람 | 리더에서 본문을 읽고 퀴즈를 풀 때 |
| 옛 형식 저장소를 쓰는 사람 | JSON 노트만 있는 저장소를 연결해 둔 채 앱을 올릴 때 |

### 흐름

1. 쓰는 사람이 `notes/<그룹>/<id>.md` 를 앞머리(제목 · 날짜) + 마크다운 본문으로 쓰고 커밋한다 → 훅이 `notes/index.json` 을 같은 커밋에 다시 만든다.
2. push 뒤 앱이 동기화하면 목록을 받고 바뀐 노트만 받는다(`sync`).
3. 앱이 목록 항목의 경로로 형식을 고르고, 마크다운이면 한도를 본 뒤 GFM 엔진으로 블록을 만든다. JSON 이면 지금처럼 읽는다.
4. 리더에 블록이 보인다 — 표 · 하위 목록 · 기울임 · 취소선 포함. 첫 문장 · 퀴즈는 같은 블록에서 나온다.
5. 해석 규칙이 바뀐 앱으로 올리면 캐시된 원문을 네트워크 없이 다시 변환한다.
