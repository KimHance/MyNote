# 노트 형식 — 마크다운 노트와 해석 엔진

| 항목 | 값 |
|---|---|
| 기능 | note-format |
| 마지막 변경 | 2026-10-07 · 처음 — 마크다운 노트(`.md`)를 GFM 엔진으로 블록에 옮기고, 이 레포 노트 22개를 파리티 시험 뒤 옮긴다 |
| 디자인 | docs/design/note-format.md |
| 항목 ID | NF-번호 (예 NF-5) |

> 동기화 순서 · 실패 종류 · 소스 계약은 `docs/spec/sync.md` 가 맡는다. 이 문서는 **본문 파일 한 개를 블록으로 바꾸는 규칙**과 그 규칙을 쓰는 이 레포 도구(목록 생성기 · 훅 · 규격 문서 · 쓰기 스킬)만 쓴다.
> 블록 · 글자 모양이 화면에 어떻게 보이는지(크기 · 색 · 기호)는 디자인 문서 몫이다. 여기엔 "무엇이 어느 블록 · 모양이 되나" 만 적는다.
> 공개 자산(`public-repos/`)의 형식은 이번에 그대로 JSON 형식 `1` 이다(`note-template`).

## 기획

### 왜

노트 본문이 블록 JSON 이라 사람이 쓰기 어렵고, GitHub 에서 열어도 읽히지 않는다. 표 · 기울임 · 하위 목록처럼 흔한 문법도 없다. 노트를 마크다운으로 쓰면 사람 · 도구 누구나 쓰고 GitHub 에서 그대로 읽힌다. 앱은 마크다운을 GFM 엔진으로 해석해 지금과 같은 블록으로 그린다. 이미 깔린 앱 · 템플릿 · 옛 저장소의 JSON 노트는 계속 읽혀야 한다.

### 누구

| 누가 | 언제 쓰나 |
|---|---|
| 노트를 쓰는 사람(이 레포 주인 · 쓰기 스킬) | 노트를 새로 쓰거나 고쳐 커밋할 때 |
| 노트를 읽는 사람 | 리더에서 본문을 읽고 퀴즈를 풀 때 |
| 옛 형식 저장소를 쓰는 사람 | JSON 노트만 있는 저장소를 연결해 둔 채 앱을 올릴 때 |

### 흐름

1. 쓰는 사람이 `notes/<그룹>/<id>.md` 를 앞머리(제목 · 날짜) + 마크다운 본문으로 쓰고 커밋한다 → 훅이 `notes/index.json` 을 같은 커밋에 다시 만든다.
2. push 뒤 앱이 동기화하면 목록을 받고 바뀐 노트만 받는다(`sync`).
3. 앱이 목록 항목의 경로로 형식을 고르고, 마크다운이면 GFM 엔진으로 블록을 만든다. JSON 이면 지금처럼 읽는다.
4. 리더에 블록이 보인다 — 표 · 하위 목록 · 기울임 · 취소선 포함. 첫 문장 · 퀴즈는 같은 블록에서 나온다.
5. 해석 규칙이 바뀐 앱으로 올리면 캐시된 원문을 네트워크 없이 다시 변환한다.

### 안 하는 것

| 안 한다 | 왜 (한 마디) |
|---|---|
| 목록 없이 폴더를 훑는 마크다운 저장소 | 결정 4 — 후속 |
| 공개 자산(규격 · 도구 · 템플릿)의 마크다운판 | 결정 5 — 후속 |
| 링크 열기 · 이미지 그리기 | 결정 10 — 후속 |
| HTML 그리기 · 수식 · 다이어그램 그리기 · 코드 색칠 | 앱이 그리지 않는다 |
| 각주 | GFM flavour 밖 |
| 인용 안의 목록 · 코드를 블록으로 그리기 | 이번엔 글자로(NF-3) — 후속 |
| 생성기가 마크다운 본문을 검사한다 | 표준 라이브러리에 마크다운 파서가 없고, 앱은 어떤 본문도 읽는다(결정 7) |
| 원격 `main` 에 올리기 | 사람이 정한다 — 콘텐츠가 앱보다 먼저 나가면 옛 앱에서 노트가 상자로 보인다 |
| 앱에서 노트 쓰기 | 읽기 전용 앱 |

## 명세

### 동작

확인 칸: `JVM` = `./gradlew test` 안의 단위 시험(시험 이름에 항목 ID). `PY` = `python3 -I -m unittest` 로 도는 파이썬 시험(시험 이름에 항목 ID, 루트 `AGENTS.md` "한 번에 검증" 명령에 들어간다). `수동` = 사람이 본다.
"블록 목록이 같다" 의 뜻: 블록 종류 · 순서 · 제목 단계 · 코드 글자 · 표 칸이 같고, 글자가 든 자리마다 **이은 글자가 같고 공백이 아닌 글자마다 모양이 같다**(같은 모양의 이웃 조각을 합쳐 보고, 공백이 어느 조각에 붙었는지는 보지 않는다).

| ID | 동작 | 받아들임 기준 | 확인 |
|---|---|---|---|
| NF-1 | **마크다운 노트 파일의 모양.** 경로 `notes/<그룹>/<id>.md`. id = 파일 이름에서 `.md` 를 뺀 것, 그룹 = 폴더 이름. 파일 맨 앞에 **앞머리**(첫 줄 `---` 부터 다음 `---` 줄까지)가 있고 `키: 값` 줄로 `title`(필수) · `date`(필수, `YYYY.MM.DD`) 를 적는다. 값 앞뒤 공백과 감싼 따옴표 한 쌍은 뺀다. 앞머리 뒤가 본문이다. 앱은 앞머리를 블록으로 만들지 않고, 제목 · 날짜는 지금처럼 목록 값을 쓴다. 앞머리가 없거나 닫히지 않은 파일은 앱이 전체를 본문으로 읽는다 | 생성기: 앞머리가 맞는 `notes/kotlin/flow.md` → 목록 `kotlin` 그룹에 `id` `flow` · 앞머리의 `title` · `date` · `path` `notes/kotlin/flow.md` · `hash` = 파일 바이트 sha256 항목이 생긴다. 앞머리 없음 · 닫히지 않음 · `title` 없음 · `date` 없음 · `date` 모양 틀림 · 모르는 키 · 빈 값이 각각 파일 경로와 이유를 말하며 실패하고 목록을 쓰지 않는다. 줄 끝이 CRLF 여도 같은 항목이다(해시만 파일 바이트대로). 앱: 앞머리가 있는 파일의 첫 블록이 본문 첫 블록이다(구분선 · 제목이 생기지 않는다). 앞머리가 닫히지 않은 파일은 첫 줄 `---` 부터 본문으로 읽힌다 | PY: `NF-1 앞머리로 목록 항목을 만든다` · `NF-1 앞머리 오류 7종은 각각 파일 경로와 실패한다` · `NF-1 CRLF 도 같은 항목이다` · JVM: `NF-1 앞머리는 블록이 되지 않는다` · `NF-1 닫히지 않은 앞머리는 본문이다` |
| NF-2 | **형식 고르기.** 목록 항목 경로가 `.md`(대소문자 무시)로 끝나면 마크다운, 그 밖은 JSON(지금 그대로)으로 읽는다. 캐시 재변환(NF-9)도 저장된 경로로 고른다 | `x.md` · `x.MD` → 마크다운 결과. `x.json` · 확장자 없음 → JSON 결과이고 캐시(`blocks_json`) 바이트가 지금 판과 같다. 같은 원문이라도 경로가 다르면 다른 형식으로 읽힌다 | JVM: `NF-2 경로 확장자로 형식을 고른다` |
| NF-3 | **지금 블록으로 가는 문법.** 제목(`#` ~ `######` · 밑줄 제목) → 제목, 단계는 그대로 1 ~ 6(보이는 모양은 지금처럼 2 이하 · 3 이상 둘). 문단 → 문단. 펜스 코드 · 들여쓴 코드 → 코드(펜스 안 줄 그대로 · 들여쓰기 유지 · 마지막 줄바꿈 없음 · 언어 표시는 버린다). 인용 → 인용 하나(안의 문단은 줄바꿈으로 잇고, 문단이 아닌 것은 그 글자를 줄로 잇는다). `-` `*` `+` 목록 → 글머리 목록, `1.` `1)` 목록 → 번호 목록. `---` `***` `___` → 구분선. 빈 줄은 블록이 아니다. 마크다운에는 `spacer` 를 만드는 문법이 없다 | 표 시험의 입력마다 기대한 블록이 나온다: `# a` → 제목 1 · `#### a` → 제목 4 · `a\n===` → 제목 1 · `a\n---` → 제목 2 · 펜스 ```` ```kotlin ```` 세 줄 → 코드 글자 세 줄(언어 없음 · 끝 줄바꿈 없음) · 네 칸 들여쓴 두 줄 → 코드 · `> a\n>\n> b` → 인용 하나 글자 `a\nb` · `> - x` → 인용 글자 `x` · `* a` · `+ a` → 글머리 · `1) a` → 번호 · `***` → 구분선 · 빈 줄 셋 → 블록 0 | JVM: `NF-3 지금 블록으로 가는 문법 표` |
| NF-4 | **글자 모양.** `**a**` `__a__` → 굵게. `` `a` `` → 코드. `*a*` `_a_` → **기울임**(새 모양). `~~a~~` → **취소선**(새 모양). 굵게 · 기울임 · 취소선은 서로 겹쳐 보인다. 코드 글자는 코드 모양만 가진다(둘러싼 굵게 등은 코드 글자에 붙지 않는다). 문단 안 줄바꿈은 공백 하나, 강제 줄바꿈(줄 끝 공백 둘 · `\`)은 줄바꿈이다 | `***a***` → `a` 가 굵게 + 기울임. `**a ~~b~~**` → `b` 가 굵게 + 취소선. `` **a `b`** `` → `b` 는 코드만. `a\nb` → `a b`. `a  \nb` → `a`·줄바꿈·`b`. 기존 3모양(일반 · 굵게 · 코드)의 결과가 JSON 과 같다(NF-11) | JVM: `NF-4 글자 모양 표` · `NF-4 겹친 모양` |
| NF-5 | **표**(새 블록). GFM 표 → 머리 행 하나 + 본문 행들. 칸마다 글자 모양(NF-4 · NF-7)이 산다. 열마다 정렬(왼쪽 · 가운데 · 오른쪽 · 없음)을 지킨다. 칸이 모자란 행은 빈 칸으로 채우고 넘치는 칸은 버린다. 이스케이프한 세로줄은 칸을 나누지 않고 세로줄 글자가 된다 | 3열 표(정렬 `:--` · `:-:` · `--:`) → 표 블록, 머리 3칸 · 본문 행 수 · 정렬 셋이 맞다. 칸 안 `**a**` 가 굵게다. 2칸뿐인 본문 행은 셋째가 빈 칸, 4칸인 행은 3칸이다. 이스케이프한 세로줄이 든 칸은 칸이 나뉘지 않고 세로줄 글자 하나를 가진다. 머리만 있는 표 → 본문 행 0 | JVM: `NF-5 표 블록` · 수동: 리더에서 넓은 표 · 좁은 창 · 큰 글자에서 읽힌다(디자인 문서 기준) |
| NF-6 | **목록 확장.** 항목은 첫 문단 글자 아래에 **하위 블록**(하위 목록 · 이어지는 문단 · 코드 · 인용 · 표)을 가진다 — 하위 목록의 종류를 지킨다. 체크 항목(`- [ ]` · `- [x]`)은 켬 · 끔이 구별되는 표시로 보인다. 번호 목록은 시작 번호를 지킨다 | `- a\n  - b\n    1. c` → 항목 `a` 아래 글머리 목록(`b`), 그 아래 번호 목록(`c`). 항목 안 펜스 코드 → 그 항목의 하위 코드 블록. 항목의 둘째 문단 → 하위 문단. `- [x] a` · `- [ ] b` → 체크 켬 · 끔이 서로 다른 항목(글자에 `[x]` 가 남지 않는다). `3. a\n4. b` → 3부터. 하위 블록이 없는 항목은 지금 항목과 같다(NF-11) | JVM: `NF-6 하위 블록` · `NF-6 체크 항목` · `NF-6 시작 번호` · 수동: 리더에서 3단 중첩 · 체크 항목이 읽힌다 |
| NF-7 | **글자로 보이는 문법.** 링크 `[a](u)` · 참조 링크 → 글자 `a`(주소는 버린다). 이미지 → 대체 글(없으면 아무것도 아님). 자동 링크 · 맨 주소 → 주소 글자. 인라인 HTML(`<T>` · `<br>` 등) → 그 글자 그대로. HTML 블록 → 원문을 코드 블록으로. `$…$` 는 수식이 아니라 글자다. `==a==` 는 글자 그대로다. 알림(`> [!NOTE]`)은 인용이고 머리 표시는 글자로 남는다. 링크 참조 정의 줄은 보이지 않는다. 이스케이프(`\*`) · 엔티티(`&amp;`)는 그 글자다. 어떤 경우도 원문 상자가 아니다 | `[문서](https://x)` → `문서`. `![그림](a.png)` → `그림`. `<https://x>` → `https://x`. `**Box<String>**` → 굵게 `Box<String>`. `<details>…</details>` 블록 → 코드 블록, 글자 = 원문. `가격 $5 와 $10` → 일반 글자 그대로. `==a==` → `==a==`. `> [!NOTE]` 다음 줄 `> a` → 인용 하나, 글자 `[!NOTE]`·줄바꿈·`a`. `\*a\*` → `*a*`. `&amp;` → `&`. 이 표의 모든 입력에서 상자 0 | JVM: `NF-7 글자로 보이는 문법 표` |
| NF-8 | **형식 오류 격리.** 마크다운 해석은 동기화로 예외를 던지지 않는다. 해석이 실패하면(예외 · 스택 넘침) 그 노트만 원문을 든 노트 전체 상자 하나가 되고, 목록에 남고, 다른 노트는 반영된다 | 해석이 실패하도록 만든 노트 하나 + 정상 노트 둘 → 동기화 성공, 정상 둘은 블록, 실패한 하나는 원문 전체를 든 상자 하나. `>` 를 5,000 단 겹친 노트 · `[` 5,000 개 노트도 동기화가 끝나고(시험 10초 안) 다른 노트가 반영된다 | JVM: `NF-8 해석 실패는 그 노트만 상자다` · `NF-8 깊은 중첩도 동기화를 멈추지 않는다` |
| NF-9 | **원문 캐시 재변환.** 해석 결과가 바뀌는 판은 해석 판 번호를 올린다. 앱이 올라가면 옛 판 번호의 캐시 행을 저장된 원문 · 경로로 네트워크 없이 다시 변환한다. 재변환은 갱신 수로 세지 않는다 | ① 옛 판이 `.md` 원문을 JSON 으로 읽어 노트 전체 상자로 캐시한 행 → 새 판 첫 동기화에서 네트워크 0회로 마크다운 블록이 된다(오프라인도). ② 옛 판의 JSON 행은 재변환 뒤 블록 결과가 그대로다. ③ 그 동기화의 갱신 수 0 | JVM: `NF-9 옛 판이 상자로 둔 마크다운 행을 원문에서 다시 만든다` · `NF-9 JSON 행은 재변환 뒤에도 같다` |
| NF-10 | **첫 문장 · 퀴즈 평문.** 마크다운 노트도 같은 규칙이다 — 첫 문장은 첫 문단(없으면 첫 목록 항목)에서. 퀴즈 평문은 블록마다 한 줄 묶음: 표는 머리 행부터 행마다 한 줄, 칸 사이 ` \| `. 하위 블록은 부모 항목 다음 줄들, 하위 항목은 깊이마다 두 칸 들여 `- `. 체크 항목은 `- [x] ` · `- [ ] `. 표는 첫 문장 후보가 아니다 | 22개 노트의 첫 문장 · 퀴즈 평문이 JSON 판과 같다(NF-11). 2×2 표의 평문이 `h1 \| h2` · `a \| b` 두 줄이다. 하위 항목 평문이 `- a` · `  - b`. 표로 시작하는 노트의 첫 문장은 표 뒤 첫 문단에서 나온다 | JVM: `NF-10 새 블록의 퀴즈 평문` · `NF-10 표는 첫 문장 후보가 아니다` |
| NF-11 | **파리티.** 이 레포 노트 22개의 옮기기 전 JSON 사본과 옮긴 마크다운 사본을 시험 자료로 고정하고, 쌍마다 블록 목록 · 첫 문장 · 퀴즈 평문이 같다. 예외는 JSON 쪽 `spacer` 블록(마크다운 문법 없음)뿐이다. 레포 `notes/` 의 모든 `.md` 는 상자 0 으로 읽힌다 | 22쌍 모두 블록 목록이 같고(`spacer` 를 뺀 JSON 쪽과 비교), 첫 문장 22개 · 퀴즈 평문 22개가 같다. 고정한 JSON 사본은 기준 커밋(`d15883f`)의 `notes/` 와 바이트가 같다. 레포 `notes/` 의 `.md` 마다 해석 결과에 상자 0 · 블록 1개 이상(`notes/` 가 없으면 시험이 실패한다 — 조용히 건너뛰지 않는다) | JVM: `NF-11 노트 22개가 JSON 과 같은 블록이 된다` · `NF-11 노트 22개의 첫 문장과 퀴즈 평문이 같다` · `NF-11 레포 마크다운 노트는 상자 없이 읽힌다` |
| NF-12 | **옛 JSON 경로.** JSON 노트 해석 · 상자 규칙 · 캐시 인코딩이 그대로다. JSON 의 닫힌 집합(블록 8종 · 모양 3종)도 그대로다 — 새 블록 · 모양은 마크다운에서만 나온다. 레포 `notes/` 에 JSON 이 없어진 뒤에도 실제 노트 시험은 고정한 JSON 사본으로 돈다 | 기존 `MyNoteJsonFormatTest` · `NoteDtoSerializationTest` · `ReparseEquivalenceTest` 가 이름 · 단정 그대로 통과한다. `레포의 실제 노트는 옛 캐시 경로와 새 경로가 같다` 가 이전 뒤에도 22개를 읽는다(건너뛰지 않는다). 템플릿 JSON 예시가 강등 0(NT-6) | JVM: 위 기존 시험 · `NT-6 템플릿 예시가 앱 파서에서 하나도 강등되지 않는다` |
| NF-13 | **목록 생성기.** `notes/gen_index.py` 가 `notes/*/*.json` 과 `notes/*/*.md` 를 함께 읽는다. 마크다운은 NF-1 로 항목을 만들고 본문은 검사하지 않는다. JSON 검사 · 상수 · 정렬 · 출력 모양은 그대로다. id 는 두 형식을 통틀어 겹치면 실패한다 | JSON 만 있는 트리에서 출력이 지금 판과 바이트가 같다(`NT-3 합성 노트 집합에서 gen_index.py 와 출력이 같다` 통과). JSON 닫힌 집합 상수가 공개 도구와 같다(NT-1 통과). `.md` 와 `.json` 이 섞인 트리 → 한 목록에 둘 다, 정렬 규칙 같음. 같은 id 의 `.md` · `.json` → 실패 · 목록 안 씀. 표준 라이브러리만 쓴다 | PY: `NF-13 마크다운과 JSON 을 한 목록으로 만든다` · `NF-13 두 형식에 같은 id 면 실패한다` · `NT-1 규격의 닫힌 집합이 gen_index.py 와 같다` · `NT-3 합성 노트 집합에서 gen_index.py 와 출력이 같다` |
| NF-14 | **커밋 훅.** `notes/<그룹>/<파일>.md` 를 스테이징(추가 · 수정 · 삭제 · 이름 바꿈)해도 목록을 다시 만들어 같은 커밋에 넣는다. 생성기가 실패하면 커밋이 멈춘다 | 임시 git 저장소에서 `.md` 하나를 추가해 커밋 → 그 커밋에 `notes/index.json` 이 함께 있고 항목이 있다. `.md` 삭제 커밋 → 항목이 빠진 목록이 같은 커밋에. 앞머리가 틀린 `.md` → 커밋 실패 · 목록 그대로 | PY: `NF-14 마크다운을 커밋하면 목록이 같은 커밋에 들어간다` · `NF-14 앞머리가 틀리면 커밋이 멈춘다` |
| NF-15 | **규격 문서 · 쓰기 스킬.** `notes/SCHEMA.md` 는 마크다운 노트를 정본으로 설명한다(NF-1 파일 모양 · NF-3 ~ NF-7 대응 표 · 옛 JSON 은 읽기 호환 절). 이 레포 `write-note` 스킬은 `notes/<그룹>/<id>.md` 를 앞머리 + 마크다운으로 쓴다 — 목록 · 해시는 만지지 않고, 앱이 글자로만 보이는 문법(NF-7)은 쓰지 않는다 | `SCHEMA.md` 의 대응 표 행이 NF-3 ~ NF-7 의 문법과 하나씩 맞다. 스킬 본문이 `.md` 경로 · 앞머리 두 키 · 목록을 안 만진다 · push 확인을 말하고, `.json` 을 새로 쓰라는 문장 · `--no-verify` 가 없다. 스킬의 예시 노트가 생성기를 통과한다 | 수동: `SCHEMA.md` 대응 표 ↔ NF-3 ~ NF-7 대조 · 스킬 본문 읽기 · 스킬 예시를 임시 파일로 생성기 통과 |
| NF-16 | **이 레포 노트 이전.** `notes/` 의 JSON 22개를 같은 경로의 `.md` 로 바꾸고 JSON 을 지운다. 북마크 · 학습 기록 키(id)는 그대로다 | 이전 뒤 `notes/` 에 노트 `.json` 0 · `.md` 22. 목록의 그룹 · 그룹 안 순서 · `id` · `title` · `date` 가 이전 전과 같고 `path` 확장자 · `hash` 만 다르다. `notes/` 의 `.md` 가 NF-11 의 마크다운 사본과 바이트가 같다. 옛 캐시(JSON 22행 + 북마크 3개) 위에서 새 목록으로 동기화 → 추가 0 · 삭제 0 · 갱신 22 · 북마크 3개 그대로. GitHub 웹에서 연 노트에서 꺾쇠 · 물결 글자가 사라지지 않는다 | JVM: `NF-16 이전 뒤 동기화는 북마크를 지키고 22개를 갱신한다` · PY: `NF-16 이전 전후 목록은 경로와 해시만 다르다` · 수동: GitHub 웹에서 `kotlin/generics` · `datastructure/bst` · `datastructure/array-list` 열어 보기 · 에뮬레이터에서 22개 노트 열람 |
