# 내 노트 저장소

GitHub 저장소에 노트를 올리면 노트 앱이 읽어 가는 **노트 저장소 템플릿**입니다.
이 템플릿으로 저장소를 만들면 예시 노트와 이미 만들어진 노트 목록(`notes/index.json`)이 함께 들어 있어, 만들자마자 앱에 연결할 수 있습니다.

## 시작하기

1. 저장소를 만듭니다. 앱의 연결 화면에서 **저장소 만들기**를 누르면 이 템플릿의 만들기 화면이 바로 열립니다. 이 페이지 위쪽의 `Use this template` → `Create a new repository` 로 직접 만들어도 됩니다. 이름과 공개 여부를 정합니다.
2. 만들어진 저장소의 주소를 복사합니다. 예: `github.com/내계정/내저장소`
3. 앱에서 **저장소 주소** 칸에 붙여 넣고 **연결**을 누릅니다.
4. 예시 노트가 홈에 보이면 끝입니다.

비공개로 만들었다면 아래 [비공개로 만들었다면](#비공개로-만들었다면)을 먼저 봅니다.

## 노트 추가

노트 하나는 파일 하나이고 `notes/<그룹>/<id>.md` 에 둡니다. 폴더 이름이 그룹이고 파일 이름이 `id` 입니다. 예시는 `notes/start/` 에 있습니다.
파일 맨 위에는 앞머리를 두고 `title`(제목) · `date`(날짜, `YYYY.MM.DD`) 두 키만 적습니다. 그 아래가 마크다운 본문입니다.

```markdown
---
title: 첫 노트
date: 2026.10.06
---
## 소제목

본문을 씁니다.
```

어느 길로 올리든 노트 파일만 올립니다. `notes/index.json` 은 올린 뒤 저장소의 작업(Actions)이 알아서 다시 만들어 같은 브랜치에 커밋하므로 손대지 않습니다.

- **웹**: 저장소 페이지에서 `Add file` → `Create new file` 로 `notes/<그룹>/<id>.md` 를 만들고 커밋합니다.
- **로컬**: 저장소를 내려받아 편집하고 push 합니다. 작업이 `index.json` 을 커밋하기 때문에 **로컬에서 이어 쓰기 전에는 `git pull` 을 한 번** 합니다.

올린 뒤 앱에서 새로고침하면 새 노트가 보입니다.

## 비공개로 만들었다면

비공개 저장소는 앱이 읽을 수 있도록 **읽기 전용 토큰**이 필요합니다. 연결할 때 앱이 `토큰이 필요합니다` 화면에서 만드는 법을 안내합니다.
종류는 세분화된 토큰, 범위는 이 저장소 하나만, 권한은 콘텐츠 읽기 전용입니다. 토큰은 앱에만 입력하고 저장소에는 적지 않습니다.

## 형식

노트는 앞머리 + 마크다운 본문입니다. 앞머리 문법 · 앱이 블록으로 그리는 문법 · 한도 · 쓰기 규칙은 규격 문서에 있습니다.

- 규격: 저장소 루트의 [`SPEC.md`](SPEC.md)
- 지원 앱 형식: `2` (저장소 루트의 `.mynote-format` 한 줄)
- 마크다운 노트를 읽으려면 마크다운을 읽는 앱 판이 필요합니다. 앱을 최신으로 올립니다.

작업은 앞머리만 검사합니다. 앞머리가 틀리면 작업이 실패하고 목록은 그대로 남습니다.
본문은 검사하지 않습니다. 앱이 그리지 못하는 문법(링크 · 이미지 · HTML · 수식 등)은 글자로 보이고, 한도를 넘은 노트는 그 노트만 상자 하나로 보입니다.

## 문제 해결

- **Actions 탭에 빨간 표시가 있습니다.** 실패한 작업을 열면 `파일 경로: 이유` 한 줄이 나옵니다. 대개 그 노트의 앞머리가 틀린 것입니다 — 첫 줄과 앞머리 끝 줄이 정확히 `---` 인지, 키가 `title` · `date` 둘뿐인지, 날짜가 `YYYY.MM.DD` 인지 봅니다. 그 파일을 규격대로 고쳐 다시 올립니다. 실패하는 동안 `index.json` 은 직전 그대로라 앱은 직전 목록을 계속 보여 줍니다.
- **앱에 "이 저장소에는 노트 목록이 없습니다" 가 뜹니다.** 주소가 이 저장소가 맞는지, `notes/index.json` 이 있는지 확인합니다. 템플릿으로 만든 저장소에는 처음부터 들어 있습니다. 템플릿으로 방금 만들었다면 잠시 뒤 다시 연결합니다.
- **작업이 `index.json` 을 올리지 못하고 실패합니다.** 조직 정책이 Actions 의 쓰기 권한을 막았거나 기본 브랜치에 브랜치 보호 규칙이 있으면 봇이 `index.json` 을 올리지 못합니다. 설정에서 쓰기 권한을 허용하거나 봇의 push 를 허용해야 합니다.
- **앱에서 노트 본문이 상자 하나로 보입니다.** 모든 노트가 그렇다면 앱이 마크다운을 읽지 못하는 옛 판입니다. 앱을 올립니다. 한 노트만 그렇다면 그 노트가 규격의 한도를 넘었습니다.
- **새 형식이 나왔습니다.** 템플릿의 새 판에서 `tools/note_tool.py` 와 `SPEC.md` 두 파일을 받아 내 저장소의 같은 자리에 덮어씁니다. 작업은 저장소 안의 `tools/note_tool.py` 를 실행합니다.
