# 노트 형식 규격 (형식 1)

이 문서는 노트 저장소의 **노트 형식**을 정하는 정본입니다. 이 형식을 따르는 저장소는 노트 앱이 그대로 읽습니다.
다른 도구(자기 스크립트 · 다른 에이전트)로 노트를 만들 때도 이 문서만 보면 됩니다. 이 문서와 검사 도구(`tools/note_tool.py`)가 어긋나면 시험이 깨집니다.

## 폴더 배치

```
.mynote-format            형식 버전 한 줄 (없으면 1)
notes/
├── index.json            도구가 만드는 목록 (직접 고치지 않습니다)
└── <그룹>/<id>.json      노트 하나 = 파일 하나
```

- 그룹은 **폴더 이름**입니다. 노트 파일 안에 그룹 칸을 두지 않습니다.
- 파일 이름은 `<id>.json` 을 권장합니다. `id` 는 저장소 전체에서 유일해야 합니다.
- 노트 폴더 이름(`notes`)은 도구의 `notes-dir` 입력으로 바꿀 수 있습니다. 목록의 `path` 는 언제나 저장소 루트 기준입니다.

## 노트 파일

```json
{
  "id": "compose-state",
  "title": "Compose 상태 관리 정리",
  "date": "2026.06.12",
  "blocks": []
}
```

| 키 | 형태 | 뜻 |
|---|---|---|
| `id` | 문자열 | 노트 식별자. 저장소 안에서 유일합니다 |
| `title` | 문자열 | 목록에 보이는 제목 |
| `date` | 문자열 | 날짜. `YYYY.MM.DD` 를 권장합니다. 목록은 날짜 내림차순입니다 |
| `blocks` | 배열 | 본문 블록. 순서가 그대로 그려지는 순서입니다 |

- 위 네 키는 모두 필수입니다. `schema` 는 있어도 되고(앞으로 쓸 자리), 그 밖의 최상위 키는 거부됩니다.
- 앱은 본문(`blocks`)을 읽고, 제목 · 날짜는 `index.json` 의 값을 씁니다.

### 블록 종류

블록은 `type` 으로 구분하며, 아래 8종뿐입니다.

| type | 필드 | 뜻 |
|---|---|---|
| `heading` | `level`(정수, 아래 표), `spans` | 섹션 제목 |
| `paragraph` | `spans` | 문단 |
| `code` | `code`(문자열, 여러 줄 가능) | 코드 블록. 원문 그대로 보입니다 |
| `quote` | `spans` | 인용 |
| `bulletList` | `items` | 글머리 목록 |
| `orderedList` | `items` | 번호 목록 |
| `divider` | (없음) | 구분선 |
| `spacer` | (없음) | 여백 |

- `items` 의 각 항목은 `{ "spans": [...] }` 입니다.
- `spans` 는 비어 있지 않은 배열이어야 합니다.

### 인라인 스타일

`spans` 의 조각은 `{ "text": "글자", "style": "bold" }` 꼴이고, `style` 을 생략하면 `text` 입니다. 스타일은 아래 3종뿐입니다.

| style | 뜻 |
|---|---|
| `text` | 일반 글자(기본값) |
| `bold` | 굵게 |
| `code` | 인라인 코드 |

`code` **블록**은 `spans` 가 아니라 `code` 문자열을 받으므로 스타일이 적용되지 않습니다.

### 헤딩 레벨

| level | 쓰임 |
|---|---|
| `2` | 섹션 제목 |
| `3` | 소제목 |

## index.json

노트 목록입니다. **그룹 이름이 최상위 키**이고 값은 그 그룹의 항목 배열입니다. 도구가 만들며 손으로 고치지 않습니다.

| 항목 키 | 뜻 |
|---|---|
| `id` | 노트의 `id` |
| `title` | 노트의 `title` |
| `date` | 노트의 `date` |
| `path` | 노트 파일의 저장소 루트 기준 경로 |
| `hash` | 노트 파일 **원본 바이트**의 sha256 (소문자 16진수) |

- 항목에는 그룹 칸이 없습니다(그룹은 상위 키).
- 그룹은 이름 순, 한 그룹 안은 날짜 내림차순 다음 `id` 순입니다. 같은 입력이면 언제나 같은 바이트가 나옵니다.
- 앱은 `hash` 를 **비교만** 합니다. 같으면 건너뛰고 다르면 다시 받습니다. 그래서 해시는 파일 바이트에서 계산해야 하고, 노트를 고치면 목록도 다시 만들어야 합니다.
- 최상위 키가 그룹 이름이라 `index.json` 에는 버전 같은 다른 칸을 넣지 않습니다.

## 형식 버전

저장소 루트의 `.mynote-format` 은 정수 한 줄입니다. 지금 형식은 `1` 입니다.

- 파일이 없으면 `1` 로 봅니다.
- 도구가 지원하는 형식보다 큰 값이거나 정수가 아니면 도구는 실패하고 `index.json` 을 쓰지 않습니다.

## 닫힌 집합과 호환 규칙

블록 종류 · 인라인 스타일 · 헤딩 레벨은 **닫힌 집합**입니다.

- 앱이 모르는 블록 `type` 은 그 블록 하나가 "원문 보기" 상자로 보일 뿐 동기화 전체를 멈추지 않습니다. 모르는 `style` 은 일반 글자로 읽습니다.
- 그래도 **검사 도구는 닫힌 집합 밖을 거부**합니다. 앱이 제대로 못 그리는 노트가 목록에 실리지 않게 하는 첫 방어선입니다.
- 새 블록 · 스타일을 더하면 형식 `1.x` 입니다. 검사 도구와 앱이 먼저 갱신되어야 합니다.
- 필드를 없애거나 뜻을 바꾸면 형식 `2` 입니다.

## 검사 도구

`tools/note_tool.py` 는 파이썬 표준 라이브러리만 씁니다.

| 명령 | 하는 일 |
|---|---|
| `check` | 노트를 검사해 오류를 `파일 경로: 이유` 한 줄씩 말하고, 하나라도 있으면 실패합니다 |
| `index` | 검사가 모두 통과할 때만 `index.json` 을 씁니다. 쓰는 파일은 그 하나뿐입니다 |
| `publish` | 형식 확인 → 검사 → `index.json` 생성 → 바뀐 때만 같은 브랜치에 커밋 · push (재사용 Action 이 부르는 진입점) |

## 예시

### 예시 노트

```json
{
  "id": "hello-notes",
  "title": "첫 노트",
  "date": "2026.01.01",
  "blocks": [
    { "type": "heading", "level": 2, "spans": [{ "text": "제목" }] },
    { "type": "paragraph", "spans": [{ "text": "본문 " }, { "text": "강조", "style": "bold" }, { "text": " 와 " }, { "text": "코드", "style": "code" }] },
    { "type": "code", "code": "val x = 1\nprintln(x)" },
    { "type": "quote", "spans": [{ "text": "인용문" }] },
    { "type": "bulletList", "items": [{ "spans": [{ "text": "항목" }] }] },
    { "type": "orderedList", "items": [{ "spans": [{ "text": "첫째" }] }] },
    { "type": "divider" },
    { "type": "spacer" }
  ]
}
```

### 예시 index.json

위 노트를 `notes/start/hello-notes.json` 에 두었을 때의 모양입니다.

```json
{
  "start": [
    {
      "id": "hello-notes",
      "title": "첫 노트",
      "date": "2026.01.01",
      "path": "notes/start/hello-notes.json",
      "hash": "(파일 원본 바이트의 sha256)"
    }
  ]
}
```
