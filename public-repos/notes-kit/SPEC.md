# 노트 형식 규격 (형식 2)

이 문서는 노트 저장소의 **노트 형식**을 정하는 정본입니다. 이 형식을 따르는 저장소는 노트 앱이 그대로 읽습니다.
다른 도구(자기 스크립트 · 다른 에이전트)로 노트를 만들 때도 이 문서만 보면 됩니다. 이 문서와 검사 도구(`tools/note_tool.py`)가 어긋나면 시험이 깨집니다.

노트는 **앞머리 + 마크다운 본문**인 `.md` 파일입니다. 옛 JSON 노트(형식 `1`)도 읽히지만 새 노트는 `.md` 로 씁니다([옛 JSON 노트 (형식 1)](#옛-json-노트-형식-1)).

> 앱은 본문을 GFM 마크다운으로 해석해 블록으로 그립니다. 그리지 못하는 문법은 글자로 보입니다.
> 원문 상자는 해석이 실패했거나 한도를 넘은 노트에만 뜹니다.
> 검사 도구는 앞머리만 검사하고 본문은 보지 않습니다. 앱이 어떤 본문이든 읽기 때문입니다.
> 마크다운 노트를 읽으려면 마크다운을 읽는 앱 판이 필요합니다. 그보다 옛 앱은 `.md` 노트를 노트마다 상자 하나로 보입니다.

## 폴더 배치

```
.mynote-format            형식 판 한 줄 (없으면 1)
notes/
├── index.json            도구가 만드는 목록 (직접 고치지 않습니다)
├── <그룹>/<id>.md        노트 하나 = 파일 하나 (앞머리 + 마크다운)
└── <그룹>/<id>.json      옛 JSON 노트 (형식 1, 읽기 호환)
```

- 그룹은 **폴더 이름**이고, 마크다운 노트의 `id` 는 **파일 이름**에서 `.md` 를 뺀 것입니다. 노트 안에 다시 쓰지 않습니다.
- `id` 는 저장소 전체에서 유일해야 합니다. 옛 `.json` 노트의 `id` 와 겹쳐도 도구가 실패합니다.
- 확장자는 소문자 `.md` · `.json` 입니다. `.MD` 같은 대소문자 변형은 도구가 실패로 말합니다.
- 노트 폴더 이름(`notes`)은 도구의 `notes-dir` 입력으로 바꿀 수 있습니다. 목록의 `path` 는 언제나 저장소 루트 기준입니다.

## 앞머리

```markdown
---
title: Compose 상태 관리 정리
date: 2026.06.12
---
## 왜 상태를 끌어올리나

상태를 가진 쪽이 **하나**여야 화면이 어긋나지 않습니다.
```

### 앞머리 키

| 키 | 형태 | 뜻 |
|---|---|---|
| `title` | 비어 있지 않은 글 | 목록에 보이는 제목 (필수) |
| `date` | `YYYY.MM.DD` | 날짜 (필수). 목록은 날짜 내림차순입니다 |

- 첫 줄이 정확히 `---`, 그 뒤 `키: 값` 줄들, 다음 줄이 정확히 `---` 입니다. 앞뒤에 공백이 붙은 `---` 는 경계가 아닙니다.
- 키는 위 표의 둘뿐입니다. 같은 키를 두 번 쓰지 않습니다.
- 값은 첫 `:` 뒤에서 앞뒤 공백과 감싼 따옴표 한 쌍을 뺀 것입니다. `title: "Flow: 기초"` 의 제목은 `Flow: 기초` 입니다. 이스케이프는 풀지 않습니다.
- 앞머리 안에 빈 줄 · `#` 줄 · 콜론 없는 줄을 두지 않습니다.
- 읽기 전에 맨 앞 BOM 을 떼고 줄 끝(CRLF · CR)을 LF 로 바꿉니다. 해시는 파일 바이트 그대로입니다.
- 앞머리는 블록이 되지 않습니다. 제목 · 날짜는 앱이 `index.json` 값을 씁니다. 본문의 `#` 제목은 본문 블록입니다.
- 앱은 경계만 봅니다. 경계가 없거나 닫히지 않으면 파일 전체가 본문이 되고, 도구는 그런 노트를 실패로 말합니다.

## 본문 — 문법과 블록

| 문법 | 앱에서 |
|---|---|
| `#` ~ `######` | 제목, 단계 1 ~ 6 (보이는 모양은 2 이하 · 3 이상 둘) |
| 밑줄 제목 `===` · `---` | 제목 1 · 2 — 쓰지 않습니다(쓰기 규칙 1) |
| 문단 | 문단. 문단 안 줄바꿈은 공백 하나, 줄 끝 공백 둘 · `\` 는 줄바꿈 |
| 펜스 코드 · 네 칸 들여쓴 코드 | 코드. 안의 줄 그대로, 언어 표시는 버립니다 |
| `>` 인용 | 인용 하나. 안의 문단은 줄바꿈으로 잇고, 문단이 아닌 것(목록 · 코드 등)은 그 글자를 줄로 잇습니다. 체크 항목은 줄 앞에 `[x]` · `[ ]` 를 남깁니다 |
| `-` `*` `+` 목록 | 글머리 목록 |
| `1.` `1)` 목록 | 번호 목록. 시작 번호를 지킵니다 |
| 목록 항목 아래 들여쓴 블록 | 그 항목의 하위 블록(하위 목록 · 문단 · 코드 · 인용 · 표). 블록 깊이는 한도 절을 봅니다 |
| `- [ ]` · `- [x]` | 체크 항목(끔 · 켬) |
| `---` `***` `___` | 구분선 |
| GFM 표 | 표. 열 정렬을 지키고, 모자란 칸은 빈 칸 · 넘치는 칸은 버립니다. 칸 맨 앞 `>` 는 글자입니다 |
| 빈 줄 | 블록이 아닙니다. 빈 여백을 만드는 문법은 없습니다 |

### 글자 모양

| 문법 | 모양 |
|---|---|
| `**a**` `__a__` | 굵게 |
| `*a*` `_a_` | 기울임. 인용 안에서는 바로 선 글자 |
| `~~a~~` `~a~` | 취소선 |
| `` `a` `` | 코드. 안의 글자는 원문 그대로 |

굵게 · 기울임 · 취소선은 서로 겹칩니다. 코드 구간에는 취소선만 붙습니다.

### 글자로만 보이는 문법

앱이 그리지 못하는 문법은 글자로 보입니다. 노트가 실패하지는 않지만 GitHub 웹과 앱에서 모양이 다르니 쓰지 않는 것이 좋습니다.

| 문법 | 보이는 글자 |
|---|---|
| 링크 `[a](u)` · 참조 링크 | `a` (주소는 버립니다) |
| 링크가 아닌 `[a]` — 정의 없는 참조(이미지 포함) · 꺾쇠 없이 공백이 든 주소 `[a](b c)` | 괄호까지 원문 글자 |
| 이미지 `![a](u)` | 대체 글 `a` |
| 자동 링크 `<https://x>` · 맨 주소 | 꺾쇠 없는 주소 |
| 인라인 HTML `<T>` · `<br>` | 그 글자 그대로 |
| HTML 블록 | 원문을 코드 블록으로 |
| 수식 `$…$` · `$$…$$` · 형광 `==a==` | 원문 글자 |
| 알림 `> [!NOTE]` | 인용. 머리 표시는 글자로 남습니다 |
| 링크 참조 정의 줄 | 보이지 않습니다 |
| 각주 `[^1]` · 각주 정의 줄 `[^1]: …` | 원문 글자 |
| 이스케이프 `\*` · 엔티티 `&amp;` · `&fjlig;` | 그 글자 |

각주 · 다이어그램 · 코드 색칠은 없습니다.

## 한도

다음 중 하나라도 넘으면 앱은 블록으로 그리지 않고 노트 전체를 한도 상자 하나로 보입니다.
그 노트는 목록에 남고 다른 노트는 그대로입니다. 검사 도구는 본문을 보지 않으므로 한도를 넘어도 실패하지 않습니다.

- 원문 크기 512KB(524,288 바이트)
- 줄 앞 컨테이너(`>` · 목록 표시) 중첩 32단
- 줄 하나의 앞부분(표시 · 들여쓰기) 64 몫 — 표시 하나 · 들여쓰기 두 칸이 한 몫
- 해석한 블록 깊이 32
- 노트 안 표 칸 4,096 — 표마다 머리 열 수 × 행 수(머리 포함)를 노트 전체로 더합니다
- 읽은 결과(블록 캐시) 1MB(1,048,576 바이트)

코드 블록 안의 줄도 셉니다. 코드 안이라도 줄 앞에 `>` 가 33개 이상 이어지거나 130칸 이상 들여 쓴 줄이 있으면
노트 전체가 상자가 됩니다.

## 쓰기 규칙

앱과 GitHub 웹에서 같은 글이 같게 보이도록 지킵니다.

1. 제목은 `#` 줄로만 씁니다. 밑줄 제목(`===` · `---`)은 쓰지 않습니다. 노트 제목은 앞머리에 있으니 본문에 `#` 로 되풀이하지 않습니다.
2. 문단 바로 다음 줄에 `---` 를 두지 않습니다. 빈 줄을 두고 씁니다. 붙이면 문단이 제목이 됩니다.
3. 굵게 · 기울임은 끝 글자가 문장부호이고 바로 뒤에 글자가 붙으면 적용되지 않습니다. 문장부호를 밖으로 내거나 공백을 둡니다.
   `**"인용"**이다` → `"**인용**"이다` · `**코드(code)**를` → `**코드(code)** 를`
4. 글자로 쓰는 `<` `~` `*` `_` `$` `==` 와 표 안의 `|` 는 백슬래시로 이스케이프합니다.
   `Box\<T>` · `\~10` · `\$5` · `\=\=` · `a \| b`. 코드 구간 · 코드 블록 안은 이스케이프하지 않습니다(백슬래시가 그대로 보입니다).
   단, 표 칸 안 코드 구간의 `|` 는 이스케이프합니다. `` `a\|b` `` 는 칸을 나누지 않고 `a|b` 로 보입니다.
5. 목록 표시(`-` · `*` · `+` · `1.` · `1)`)로 시작하는 줄을 문단의 이어지는 줄로 두지 않습니다. 앱은 번호 · 빈 항목과 상관없이
   그 줄에서 문단을 끊습니다(CommonMark 와 다릅니다). 목록은 빈 줄을 두고 시작합니다.

## index.json

노트 목록입니다. **그룹 이름이 최상위 키**이고 값은 그 그룹의 항목 배열입니다. 도구가 만들며 손으로 고치지 않습니다.

| 항목 키 | 뜻 |
|---|---|
| `id` | 노트의 `id` (마크다운은 파일 이름) |
| `title` | 노트의 제목 (마크다운은 앞머리 `title`) |
| `date` | 노트의 날짜 (마크다운은 앞머리 `date`) |
| `path` | 노트 파일의 저장소 루트 기준 경로 |
| `hash` | 노트 파일 **원본 바이트**의 sha256 (소문자 16진수) |

- 항목에는 그룹 칸이 없습니다(그룹은 상위 키).
- 그룹은 이름 순, 한 그룹 안은 날짜 내림차순 다음 `id` 순입니다. 같은 입력이면 언제나 같은 바이트가 나옵니다.
- 앱은 `hash` 를 **비교만** 합니다. 같으면 건너뛰고 다르면 다시 받습니다. 그래서 해시는 파일 바이트에서 계산해야 하고, 노트를 고치면 목록도 다시 만들어야 합니다.
- 앱은 `path` 의 확장자로 형식을 고릅니다. `.md` 는 마크다운, 그 밖은 JSON 입니다.
- 최상위 키가 그룹 이름이라 `index.json` 에는 버전 같은 다른 칸을 넣지 않습니다.

## 형식 판

저장소 루트의 `.mynote-format` 은 정수 한 줄입니다. 지금 형식은 `2` 입니다.

- 판 값은 "이 저장소를 읽으려면 이 판 이상을 아는 도구가 필요하다" 는 뜻입니다.
- 파일이 없으면 `1` 로 봅니다.
- 도구가 지원하는 판보다 큰 값이거나 정수가 아니면 도구는 실패하고 `index.json` 을 쓰지 않습니다.
- 판 값은 무엇을 읽을지 고르지 않습니다. 판이 없거나 `1` 인 저장소에서도 도구는 `.md` 와 `.json` 을 모두 읽습니다.

## 옛 JSON 노트 (형식 1)

`notes/<그룹>/<id>.json` 노트도 앱과 도구가 읽습니다. 새 노트는 `.md` 로 쓰고, 옛 노트를 고칠 때는 같은 `id` 의 `.md` 로 옮깁니다.
JSON 노트는 아래 닫힌 집합으로만 읽습니다. 표 · 기울임 · 취소선 · 하위 블록 · 체크 · 시작 번호는 JSON 에 없습니다.

### 노트 파일 (JSON)

```json
{
  "id": "compose-state",
  "title": "Compose 상태 관리 정리",
  "date": "2026.06.12",
  "blocks": []
}
```

| 키 | 형태 | 뜻 |
|---|---|---|
| `id` | 문자열 | 노트 식별자. 저장소 안에서 유일합니다 |
| `title` | 문자열 | 목록에 보이는 제목 |
| `date` | 문자열 | 날짜. `YYYY.MM.DD` 를 권장합니다 |
| `blocks` | 배열 | 본문 블록. 순서가 그대로 그려지는 순서입니다 |

- 위 네 키는 모두 필수입니다. `schema` 는 있어도 되고(앞으로 쓸 자리), 그 밖의 최상위 키는 거부됩니다.
- 앱은 본문(`blocks`)을 읽고, 제목 · 날짜는 `index.json` 의 값을 씁니다.
- 한도 중 읽은 결과(블록 캐시) 크기만 JSON 노트에도 걸립니다. 넘으면 노트 전체가 한도 상자입니다.

### 블록 종류

블록은 `type` 으로 구분하며, 아래 8종뿐입니다.

| type | 필드 | 뜻 |
|---|---|---|
| `heading` | `level`(정수, 아래 표), `spans` | 섹션 제목 |
| `paragraph` | `spans` | 문단 |
| `code` | `code`(문자열, 여러 줄 가능) | 코드 블록. 원문 그대로 보입니다 |
| `quote` | `spans` | 인용 |
| `bulletList` | `items` | 글머리 목록 |
| `orderedList` | `items` | 번호 목록 |
| `divider` | (없음) | 구분선 |
| `spacer` | (없음) | 여백 |

- `items` 의 각 항목은 `{ "spans": [...] }` 입니다.
- `spans` 는 비어 있지 않은 배열이어야 합니다.

### 인라인 스타일

`spans` 의 조각은 `{ "text": "글자", "style": "bold" }` 꼴이고, `style` 을 생략하면 `text` 입니다. 스타일은 아래 3종뿐입니다.

| style | 뜻 |
|---|---|
| `text` | 일반 글자(기본값) |
| `bold` | 굵게 |
| `code` | 인라인 코드 |

`code` **블록**은 `spans` 가 아니라 `code` 문자열을 받으므로 스타일이 적용되지 않습니다.

### 헤딩 레벨

| level | 쓰임 |
|---|---|
| `2` | 섹션 제목 |
| `3` | 소제목 |

### 닫힌 집합과 호환 규칙

블록 종류 · 인라인 스타일 · 헤딩 레벨은 **닫힌 집합**입니다.

- 앱이 모르는 블록 `type` 은 그 블록 하나가 "원문 보기" 상자로 보일 뿐 동기화 전체를 멈추지 않습니다. 모르는 `style` 은 일반 글자로 읽습니다.
- 그래도 **검사 도구는 닫힌 집합 밖을 거부**합니다. 앱이 제대로 못 그리는 노트가 목록에 실리지 않게 하는 첫 방어선입니다.
- 형식 `1` 에는 블록 · 스타일을 더하지 않습니다. 새 모양은 마크다운 노트로 씁니다.

## 검사 도구

`tools/note_tool.py` 는 파이썬 표준 라이브러리만 씁니다. 마크다운 노트는 앞머리만, JSON 노트는 닫힌 집합을 검사합니다.

| 명령 | 하는 일 |
|---|---|
| `check` | 노트를 검사해 오류를 `파일 경로: 이유` 한 줄씩 말하고, 하나라도 있으면 실패합니다 |
| `index` | 검사가 모두 통과할 때만 `index.json` 을 씁니다. 쓰는 파일은 그 하나뿐입니다 |
| `publish` | 형식 판 확인 → 검사 → `index.json` 생성 → 바뀐 때만 같은 브랜치에 커밋 · push (재사용 Action 이 부르는 진입점) |
