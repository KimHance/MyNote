# check-notes

저장소의 노트가 규격(`${CLAUDE_PLUGIN_ROOT}/SPEC.md`)에 맞는지 검사 도구로 확인하고, 틀린 곳을 알아듣게 풀어 말합니다. **이 스킬은 파일을 고치지 않습니다.** 고칠 방법을 제안만 하고, 고치는 일은 사용자가 시키면 `write-note` 로 합니다.

## 검사

저장소 루트에서 실행합니다.

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/note_tool.py" check
```

- 노트 폴더가 `notes` 가 아니면 `--notes-dir <폴더>` 를 붙입니다.
- 통과하면 `✓ 노트 N개가 규격에 맞습니다` 한 줄이 나옵니다.
- 실패하면 오류가 **`파일 경로: 이유`** 한 줄씩 나옵니다. 이 줄 형식을 그대로 받아서 씁니다.

## 결과 풀이

오류 줄마다 다음 네 가지를 말합니다.

1. **어느 파일** — 줄 앞의 파일 경로
2. **무엇이 틀렸나** — 줄 뒤의 이유를 쉬운 말로
3. **규격의 어느 절을 보면 되나** — `${CLAUDE_PLUGIN_ROOT}/SPEC.md` 의 해당 절(블록 종류 · 인라인 스타일 · 헤딩 레벨 · 노트 파일 · 형식 버전 · 닫힌 집합과 호환 규칙)
4. **고친 예** — 틀린 부분을 맞게 고친 JSON 조각

여러 파일이 틀렸으면 파일별로 묶어 보여 줍니다. 통과했으면 통과했다고만 말하고 더 만들어 내지 않습니다.

## 파이썬이 없으면

`python3` 가 없거나 도구가 안 돌면, `${CLAUDE_PLUGIN_ROOT}/SPEC.md` 를 읽고 노트를 눈으로 대조합니다. 확인할 것은 최상위 네 키(`id` · `title` · `date` · `blocks`), 블록 `type` 이 닫힌 집합 안인지, `spans` 가 비어 있지 않은지, `style` 과 헤딩 `level` 이 집합 안인지입니다. 도구로 확인하지 못했다고 말해 줍니다.

## 하지 않는 것

- 노트 파일을 고치지 않습니다. `index.json` 도 만들지 않습니다.
- 도구가 통과시킨 노트를 규격 밖이라고 우기지 않습니다.
