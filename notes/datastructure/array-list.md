연속된 메모리에 같은 타입을 줄세운 자료구조. **인덱스로 즉시 접근** 해야 할 때 1순위. 고정 크기가 **배열**, 자동으로 늘어나는 게 `ArrayList` (동적 배열).

## 내부 구조 — 동적 배열

`ArrayList` 는 내부에 고정 배열을 두고, 꽉 차면 **보통 1.5\~2배 큰 배열을 새로 할당해 복사** 한다. 그래서 append 는 대부분 `O(1)` 이지만 가끔 리사이즈로 `O(n)` — 평균내면 **분할상환(amortized) O(1)**.

```
용량(capacity) 4, 크기(size) 4 → 가득 참
[ a ][ b ][ c ][ d ]

add(e): 용량 8 새 배열 할당 후 복사 (이 순간만 O(n))
[ a ][ b ][ c ][ d ][ e ][ _ ][ _ ][ _ ]
                         ▲ 이후 add 는 빈 칸에 O(1)

  size = 논리적 개수,  capacity = 실제 배열 길이 (size 이하 구간만 사용)
```

### 복잡도

```
연산              평균        최악
──────────────────────────────────
인덱스 접근 get/set O(1)        O(1)
탐색 (값으로)      O(n)        O(n)
끝에 추가 add      O(1)*       O(n)   *분할상환, 최악=리사이즈
중간 삽입/삭제      O(n)        O(n)   뒤 원소 시프트
끝에서 삭제         O(1)        O(1)
```

## Kotlin 사용

```
val list = ArrayList<Int>()      // 또는 mutableListOf<Int>()
list.add(1); list.add(2)         // 분할상환 O(1)
val x = list[0]                  // O(1) 인덱스 접근
list.add(0, 99)                  // 맨 앞 삽입 → O(n) (전부 시프트)

// 미리 용량을 알면 리사이즈를 피한다
val sized = ArrayList<Int>(1_000)  // 초기 capacity 지정
```

- 랜덤 접근·순회가 잦으면 ArrayList. **앞/중간 삽입·삭제** 가 잦으면 `LinkedList` 고려(형제 노트).
- 대략적 크기를 알면 초기 capacity 를 줘서 복사 비용을 없앤다.
- 안드로이드에서 작은 정수 키맵은 `SparseArray` · `ArrayMap` 가 메모리 효율적.

> **요약: 연속 메모리라 인덱스 접근 O(1), 동적 배열은 리사이즈를 분할상환해 append O(1). 중간 삽입/삭제는 O(n) — 그 패턴이면 LinkedList 를 봐라.**
