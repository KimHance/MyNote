# 노트 저장소 연결 · 입구 구역 — 구현 핸드오프

> 대상: Claude Code. MyNote (Kotlin + Compose + Navigation 3, MVI). 디자인 px = dp (1 : 1). 스크린샷은 1x.
> 원본: `Repo Connect Entry.dc.html` (프로젝트 루트). 후보 A · 후보 B · 공통 세 구역, 각 장의 캡션이 이 문서의 상태 설명과 같습니다.
> `design_handoff_repo_connect/` 의 **추가분**입니다. 그 문서의 토큰 · 타이포 · 버튼 · 화면 구성 규칙을 그대로 따르며, 여기에는 바뀌거나 더해진 것만 적습니다.
> 저장소는 모두 가짜 예시입니다: 링크 칸 `octo-learner/android-notes` · 템플릿 `octo-learner/notes-template` · 목록 없는 예시 `octo-learner/markdown-notes`.

무엇을 더하나: 노트 저장소가 아직 없는 사람을 위한 **입구 구역**을 연결 화면에 더하고, 목록 없음(RC-9) 상자에 두 길(`저장소 만들기` · `형식 안내 보기`)을 더합니다. 앱은 읽기 전용이라 입구 버튼은 GitHub 템플릿 생성 화면(`octo-learner/notes-template` 기준)을 **외부 브라우저로 열 뿐**입니다. 앱은 저장소를 만들지 않고, 입구는 연결 상태 · 입력을 바꾸지 않으며 요청도 내지 않습니다.

## 3. 후보 A / B

첫 실행 루트의 구역 순서만 다릅니다. 쌓은 화면과 목록 없음 상자는 후보와 무관하게 한 벌(§4)입니다.

| | A · 링크 먼저 | B · 입구 먼저 |
|---|---|---|
| 세로 순서 | H1 → 안내 → 칸 → 이유 → `연결` → `또는` → 입구 | H1 → 입구 → `또는` → 안내 → 칸 → 이유 → `연결` (안내 글이 칸 바로 위로 내려감) |
| 가로 두 단 | 왼쪽 링크 · 오른쪽 입구 | 왼쪽 입구 · 오른쪽 링크 |
| 가로 키보드 열림 | 칸 + `연결` 까지 본문이 올라가 H1 · 안내가 위로 잘림. 오른쪽 입구 단도 같은 만큼 밀려 제목이 가려지고 단계 아래쪽 · 버튼만 남음 | 같은 스크롤. 링크가 오른쪽 단이라 칸 + `연결` 이 키보드 위 오른쪽에, 왼쪽 입구 단은 제목이 잘려 일부만 남음 |
| 알아본 결과가 생길 때 | 링크 구역이 25dp 늘어 `연결` 과 그 아래 입구가 함께 25dp 밀림. 칸은 제자리 | 입구 · 칸은 제자리, `연결` 만 25dp 밀림 |
| 입구가 숨을 때(목록 없음) | 칸 · `연결` 이 **튀지 않음**(숨는 구역이 아래) | 칸이 위로 약 310dp **튐**(숨는 구역이 위) — 상자가 나타나는 순간 칸 위치가 바뀜 |
| 큰 글자 ×1.3 첫 화면 | 링크 구역 + `연결` 이 첫 화면, 입구는 스크롤 아래 | 입구가 첫 화면을 차지, 칸 · `연결` 은 스크롤해야 보임 |

보이는 대로의 장단:
- **A** — 저장소가 있는 대부분의 사람에게 칸이 바로 보이고, 오류 · 큰 글자 · 키보드에서 칸 위치가 흔들리지 않습니다. 입구는 `또는` 아래라 저장소가 없는 사람에게는 한 번 더 내려 읽어야 보입니다.
- **B** — 저장소가 없는 사람에게 할 일이 먼저 보이고, 세 단계 끝(`이 앱의 주소 칸에 붙여 넣고 연결합니다.`)이 바로 아래 칸으로 이어집니다. 대신 저장소가 있는 사람은 칸까지 입구를 지나야 하고, 큰 글자에서는 칸이 첫 화면 밖으로 나가며, 목록 없음에서 칸이 튑니다.

## 4. 공통 — 쌓은 화면 · 목록 없음 상자

**쌓은 화면**(설정 › 저장소 바꾸기): 상단 바 뒤로 + `저장소 바꾸기`, H1 없음, 위 여백 12. 순서는 후보와 무관하게 **링크 구역 첫째 → `또는` → 입구 구역 둘째**. compact · 852 모두 스크롤 없이 들어갑니다.

**목록 없음(RC-9)**: 칸 `octo-learner/markdown-notes` + 알아본 결과 줄 + warn 상자. **입구 구역과 `또는` 은 숨습니다**(같은 길이 상자에 있으므로). `연결` 은 활성(재시도).
상자는 시각적으로 하나(warn 8% 면 · 20% 테두리 · 반경 12)이고 안은 둘로 나뉩니다.
1. **글 영역**(낭독 영역, `liveRegion = LiveRegionMode.Polite`): 패딩 12/14, 18dp 경고 아이콘 + 10dp + 두 문장(14 warnText, 사이 4dp).
   `이 저장소에는 노트 목록이 없습니다. 이 앱은 노트 목록이 있는 저장소만 읽을 수 있습니다.` / `방금 템플릿으로 만들었다면 잠시 뒤 다시 연결하세요.`
2. 좌우 14dp 안쪽 1dp 구분선(warn 20%) 뒤 **버튼 줄**(낭독 영역 **밖**의 형제, 위아래 12dp, `FlowRow` 간격 8): `저장소 만들기`(보조 + External) · `형식 안내 보기`(조용한 text2 글자 버튼 + External). 한 줄에 안 들어가면 줄을 바꾸고 라벨은 한 줄 고정.

## 6. 접근성

- **세 단계 순서 낭독**: 각 행을 `Modifier.semantics(mergeDescendants = true)` 로 묶어 위에서 아래로 읽습니다. 번호 배지는 **장식**(`clearAndSetSemantics {}` / `invisibleToUser`)이고 숫자를 따로 읽지 않습니다. 순서는 목록 의미(`collectionInfo` 3행, 각 행 `collectionItemInfo`)로 전달해 "3개 중 1번째" 처럼 읽힙니다.
- 입구 제목 `저장소가 아직 없나요?` 는 `heading()`.
- **버튼 이름에 외부 브라우저 열림**: 화면 글자는 그대로 두고 접근성 이름만 덧붙입니다.
  `저장소 만들기, 외부 브라우저에서 열립니다` · `형식 안내 보기, 외부 브라우저에서 열립니다`. External 아이콘은 장식(`contentDescription = null`).
- 입구 버튼은 상태를 바꾸지 않으므로 누른 뒤 포커스는 버튼에 그대로 남고, 앱으로 돌아와도 입력 · 연결 상태가 그대로입니다.
- **목록 없음 상자 포커스 순서**(13번 장): ① `저장소 주소` 칸 → ② 상자 글(낭독 영역, Polite 로 나타날 때 한 번 읽힘, **포커스 없음**) → ③ `저장소 만들기` → ④ `형식 안내 보기` → ⑤ `연결`. 버튼 줄이 낭독 영역 밖이라 상자가 나타날 때 버튼 이름까지 낭독되지 않습니다.
- 터치 48dp 이상(`minimumInteractiveComponentSize`), 라벨 한 줄 고정, 큰 글자에서 버튼 줄은 `FlowRow` 로 줄바꿈.

## 10. 수용 기준

- [ ] 새 색 토큰이 없다(§1 표의 값만 쓴다)
- [ ] 화면의 accent 면 버튼은 `연결` 하나뿐이고 `저장소 만들기` 는 보조 버튼(surface2 + 1dp border)이다
- [ ] 입구 구역은 카드 · 구역 배경 없이 링크 구역과 같은 층 · 같은 폭이다. 링크 구역에 새 제목이 없다
- [ ] `연결` 은 링크 구역 안에 있고 두 구역 사이에 끼지 않는다
- [ ] compact 360×800 · 852×800 · 가로 800×360 첫 실행 루트가 키보드 닫힘에서 스크롤 없이 두 구역을 보인다
- [ ] 가로 첫 실행 루트는 H1 전폭 + 좌우 두 단이다
- [ ] 쌓은 화면은 후보와 무관하게 링크 첫째 · 입구 둘째다
- [ ] 목록 없음에서 입구 구역과 `또는` 이 숨고, 상자 안 버튼 줄이 낭독 영역 밖 형제다
- [ ] 입구 · 상자 버튼은 외부 브라우저만 열고 연결 상태 · 입력 · 요청을 바꾸지 않는다
- [ ] 번호 배지는 낭독되지 않고 세 단계는 순서대로 읽힌다
- [ ] 두 External 버튼의 접근성 이름에 `외부 브라우저에서 열립니다` 가 붙는다
- [ ] 큰 글자 ×1.3 에서 상자 버튼 줄이 줄바꿈되고 라벨이 잘리지 않는다
- [ ] 금지어가 어디에도 없다
